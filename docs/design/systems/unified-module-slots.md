# Feature: 범용 모듈 슬롯 통합

## 목적

함선 부위마다 분리된 시설 슬롯을 하나의 범용 모듈 슬롯 풀로 통합한다. 무기실·동력로·엔진·선체·레이더·실드 구분은 장착 제한이 아니라 모듈 tag와 아이콘 정체성으로 유지하고, 이후 tag 조합 시너지의 기반으로 사용한다.

## 규칙

1. `PlayerAugmentRegistry`는 범용 슬롯 배열 하나만 소유한다.
2. 범용 슬롯은 5칸으로 시작하고 오퍼 1회를 소비해 1칸씩, 최대 15칸까지 확장한다.
3. 모든 `FACILITY_EFFECT` 모듈은 tag와 무관하게 빈 범용 슬롯에 장착할 수 있다.
4. 범용 슬롯이 가득 차면 전체 장착 모듈 중 하나를 선택해 교체한다.
5. `PlayerAugment.module_tags`가 분류 정본이다. 기존 `facility_id`는 호환용 primary tag로 유지한다.
6. `weapon_room`, `hangar`, `engine`, `hull`, `radar`, `shield`의 표시명·아이콘은 `ShipFacilityDefinition`을 tag 메타데이터로 재사용한다.
7. tag는 장착 제한이나 추가 배율을 만들지 않는다. tag 시너지 규칙은 후속 feature 범위다.
8. 동일 모듈 중복 설치와 `FacilityModuleEffect` Kind별 곱/합 계산은 기존과 동일하다.
9. 무기실·엔진 등 6개 시설 타일과 선체 연결선은 표시하지 않는다. tag는 데이터와 슬롯 아이콘 선택에만 사용한다.
10. 오퍼 UI에는 부위 선택 대신 단일 범용 슬롯 확장 액션을 제공한다.

## UI

- 범용 슬롯 랙: 기존 모듈 표기와 같은 28px 폭의 flat-top 육각형으로 최대 15칸을 5열×3행 벌집으로 표시한다. 열은 반 칸씩 세로로 어긋나고 모든 육각형은 변을 맞대어 빈틈없이 맞물린다.
- 빈 슬롯은 빈 육각 프레임으로, 장착 슬롯은 당분간 primary tag의 기존 시설 아이콘으로 표시한다.
- 슬롯 호버 시 상세 줄에서 슬롯 번호·tag 표시명·실제 장착 모듈명을 확인한다. 기본 상세는 장착/용량과 빈 슬롯 수를 표시한다.
- 확장 액션에 포커스·호버하면 현재 용량 다음 위치에 육각형 한 칸을 추가로 점멸한다. 이 연출은 오퍼로 게임이 일시정지된 동안에도 진행한다.
- 교체 오버레이: 최대 15개 범용 슬롯을 스크롤 목록으로 표시하고 각 행에 모듈명과 primary tag를 표시.
