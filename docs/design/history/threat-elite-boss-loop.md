# Threat 엘리트 · 보스 진행 루프 (초안)

> 과거 기능 작업의 설계·결정 이력입니다. 아래 수치·상태·문서 운영 지침은 당시 기록이며 현재 구현 기준이 아닙니다. 현재 기준은 [통합 기획서](../README.md)를 따릅니다. 미구현 제안은 별도 확정 없이 구현하지 않습니다.

## 의도

시간 기반 Threat 진행을 단순한 적 로스터 확장 이상의 **전투 마일스톤**으로 만든다. 60초마다 시작되는 엘리트 전투가 긴장을 만들고, 처치로 확정되는 Threat 상승과 적 증강 선택은 다음 구간의 규칙을 바꾼다. 여러 마일스톤의 끝에는 보스를 배치해 런의 장을 구분한다.

이 문서는 방향과 시스템 경계를 정한 초안이다. `TBD`는 아직 수치나 정책을 확정하지 않은 빈칸이며, 이를 채우기 전에는 구현을 시작하지 않는다.

## 제안 플레이 루프

```text
일반 전투
  → 60초 타이머 완료
  → 엘리트 경고 / 일반 Encounter 정리 또는 동결
  → 엘리트 등장
  → 엘리트 처치 확인 / Threat 상승
  → 적 증강 3지선다 선택
  → 일반 전투 재개

매 N번째 Threat 상승
  → 보스 경고
  → 보스 등장 · 처치
  → [TBD: 보스 처치 보상]
  → 다음 구간으로 재개 또는 런 종료
```

### 권장 이벤트 우선순위

동일 프레임에 일반 생성 타이머와 엘리트 타이머 완료가 겹쳐도, `boss > elite > augment offer > normal encounter` 순서로 하나만 시작한다. 이렇게 하면 보스와 엘리트가 겹쳐 생성되거나, 증강 선택 UI 아래에서 일반 적이 계속 누적되는 문제를 피할 수 있다.

엘리트 전투와 적 증강 오퍼 중에는 일반 Encounter 생성기를 **일시 정지**한다. 이미 살아 있는 일반 적은 유지하고, 오퍼 선택 완료 뒤 새 생성 간격으로 재개한다. 보스 정책은 후속으로 남긴다.

## 상태 모델 (제안)

| 상태 | 진입 | 종료 | 책임 |
|---|---|---|---|
| `NORMAL` | 런 시작 또는 보상 종료 | 60초 타이머 완료 | 일반 Encounter 생성 |
| `ELITE_COMBAT` | 타이머 완료·다음 Threat 엘리트 생성 | 엘리트 사망·Threat 상승 | 엘리트 추적, 일반 스폰 억제 |
| `ENEMY_AUGMENT_OFFER` | 엘리트 처치 | 선택/닫기 완료 | 기존 적 증강 오퍼·레지스트리 적용 |
| `BOSS_WARNING` | 보스 주기 Threat | 경고 종료 | 보스 텔레그래프 |
| `BOSS_COMBAT` | 보스 생성 완료 | 보스 사망 | 보스 추적, 일반 스폰 정책 |
| `POST_BOSS` | 보스 처치 | 다음 구간 진입/런 종료 | 보상·난이도 재설정 |

`AugmentProgressionController`는 Threat 카운터와 엘리트 게이트 상태를 소유한다. 별도 `ThreatEliteController`가 Threat 변화와 엘리트 사망을 구독·조율한다. 기존 `EnemyGenerator`는 게이트가 닫혔을 때만 일반 Encounter를 요청하며, 엘리트는 명시적 전용 스폰 요청을 사용한다.

## 데이터 경계 (제안)

| 데이터 | 역할 | 핵심 필드 초안 |
|---|---|---|
| `threat_elite_single` | 엘리트 원형과 이동 연결 | 전용 scene, single layout, entry/patrol sequence |
| `BossDefinition` | 보스의 단계/패턴/종료 정책 | `id`, `scene`, `min_cycle`, `phases`, `telegraph`, `completion_reward` |
| `ThreatMilestoneRules` | 엘리트·보스 주기와 예외 | `elite_every_threat`, `boss_every_n_threats`, `first_boss_threat`, `skip_policy` |
| `MilestoneRunState` | 런 중 한 번만 유지할 상태 | `current_threat`, `threats_since_boss`, `active_milestone_id`, `phase` |

엘리트는 전용 `EliteFighter` 씬과 상단 순찰, 전방 2연사, 플레이어 현재 위치를 추적하는 12발 집중 연사를 사용한다. 보스는 이미 존재하는 `Enemy.is_boss`와 `bosses` 그룹을 사용하되, 플래그만으로 스폰·패턴을 해결하지 않는다.

## 보상 및 난이도 원칙

- 엘리트 처치 성공 시 Threat를 1 올리고 적 증강 오퍼를 연다. 타이머 완료만으로는 Threat나 오퍼가 진행되지 않는다.
- 오퍼는 기존 적 증강 풀과 `max_stacks`/획득 한도 규칙을 그대로 존중한다.
- 후보가 부족할 때의 대체 보상은 명시적으로 정한다. 빈 오퍼나 중복 강제 선택은 허용하지 않는다.
- 엘리트는 다음 구간 난이도를 고정적으로 올리는 관문이며, 보스는 별도의 패턴 숙련도를 요구하는 전투로 구분한다.
- 보스 처치 뒤의 보상은 적 증강과 같은 성격으로 고정하지 않는다. 플레이어 보상, 회복, 다음 장 진입 등은 밸런스 목표에 따라 선택한다.

## 검증 기준 초안

- 60초 타이머 완료가 엘리트 전투를 정확히 한 번 시작하고, 엘리트 처치가 Threat를 정확히 1 올리며 일반 Encounter와 중복되지 않는다.
- 엘리트 처치 이전에는 적 증강 오퍼가 열리지 않으며, 처치 뒤에는 정확히 한 번 열린다.
- 적 증강 선택 결과가 기존 레지스트리에 적용되고 획득 한도도 유지된다.
- N번째 Threat에서 엘리트 대신(또는 확정된 정책에 따라 뒤이어) 보스 전투가 정확히 한 번 시작한다.
- 일시정지, 플레이어 사망, 화면 이탈, 오퍼 후보 고갈, 여러 Threat 누적을 결정된 정책대로 재현 가능한 테스트로 검증한다.

## 구현 후보 범위 (결정 후)

- `components/` — 마일스톤 상태/사망 감지/텔레그래프 구성요소
- `enemies/`, `resources/enemy_spawns/` — 엘리트·보스 씬, 전용 행동, 정의 리소스
- 진행 컨트롤러와 `enemy_generator.gd` — Threat 구독 및 일반 스폰 게이트
- `menus/`, HUD — 경고·체력바·증강 오퍼 연결
- `tests/` — 상태 전이, 중복 방지, 오퍼/카운터 회귀 테스트
