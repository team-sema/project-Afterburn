# 씬 플로우

## 기획 의도

중앙 전장을 유지하면서 좌우 HUD로 상태를 읽고, 선택 중에는 전투를 멈춰 판단 시간을 제공한다.

## 확정된 현재 동작

거대 항모 독립 시험은 `labs/bosses/carrier/carrier_boss_lab.tscn`을 F6으로 열거나 Lab 허브에서 선택한다. 중앙 전장 상단에 보스 전체 HP를 고정 표시하고 좌측에는 재시작·일시정지·허브 복귀, 우측에는 피격 횟수와 경과 시간을 표시한다. 규칙은 [거대 항모](bosses/carrier.md)를 따른다. 본 게임 HUD와 엘리트 추적형 HP바는 그대로 유지한다.

개발 시험의 공통 입구는 저장소 루트의 `lab_hub.tscn`이다. 아래 Lab을 목록에서 방향키/Enter로 선택한다. 허브에서 연 Lab은 F1로 목록에 복귀하며, 씬은 하나씩 실행한다. 기존 개별 씬의 F6 실행도 유지한다. 본 게임 시작 씬은 변경하지 않는다. 탄막 스크립트 작업 규칙은 [전투](combat.md)를 따른다.

Lab 배치: 허브만 루트에 두고 각 Lab은 `labs/<주제>/` 아래에 둔다. 새 Lab을 만들면 `lab_hub.gd`의 `LABS` 목록에도 등록한다. 보스 Lab은 보스마다 `labs/bosses/<보스>/` 폴더를 두고 허브에 `보스 · <이름>`으로 등록한다. 허브 복귀용 공용 스크립트는 `labs/lab_return.gd`다.

| 허브 항목 | 진입 씬 |
|---|---|
| 탄막 · 패턴 스크립트 | `labs/bullet/bullet_lab.tscn` (예제별 바로가기 `labs/bullet/presets/`는 허브에 따로 두지 않는다) |
| 보스 · 거대 항모 | `labs/bosses/carrier/carrier_boss_lab.tscn` |
| 보스 · 벽 | `labs/bosses/wall/wall_boss_lab.tscn` |
| 엘리트 · 스나이퍼 공격 패턴 | `labs/enemy_attack/enemy_attack_lab.tscn` (Elite Awl·Fighter·Bomb·Caster·Sniper) |
| 무기 · 증강 · 적 소환 | `labs/weapons/weapon_test_lab.tscn` |
| 증강 카드 · UI | `labs/augment_cards/augment_frame_test.tscn` |

무기 · 증강 · 적 소환 Lab(`weapon_test_lab`)은 640×360 기준에서 좌우 170px 패널과 가운데 300px 전장으로 나눈다. 패널은 Lab 전용 테마(`labs/weapons/weapon_test_lab_theme.tres`, Mulmaru 10px · 얇은 스크롤바 · 작은 SpinBox 화살표)를 쓰고, 버튼은 높이 16px(스폰 목록은 14px)로 이름이 잘리지 않게 한다.

- **좌측 · 적 스폰**: 1회 스폰 수 → Encounter 목록 → 반복 스폰 간격·지속 스폰 → `표적 NN` · `전장 정리`. 목록은 `본 게임 풀`(`main_encounter_pool`) · `엘리트 · 보스` · `특수 스폰`(`sniper_reinforcement`·`elite_escort_drone_pair`) · `기타 · 레거시` 묶음으로 나누고, 행마다 왼쪽 정렬 스폰 버튼과 `반복` 토글을 둔다.
- **우측 · 장비**: 슬롯 버튼(번호 + 장착 무기 아이콘) → 무기 목록(장착 무기는 녹색 · `장착`) → 선택 무기 전용 모듈(활성 시 녹색 · `Lv.N`, 사용법은 툴팁) → `모듈 초기화` · `슬롯 비우기`. 무기 목록과 모듈 목록은 남은 높이를 반씩 나눈다.
- **가운데 배지**: 평소 `C 플레이어 증강 · V 적 증강`, 증강을 고르면 마지막 결과를 보인다.
- **C/V 증강 선택**: 화면을 덮는 패널에 분류 탭과 2열 카드 그리드를 둔다. 카드는 아이콘 · 이름 · 배지 · 설명 2줄이다. 플레이어(C)는 시설 모듈, 적(V)은 `스탯` · `행동` · `편성 · 규칙` · `진화` 탭이다. 배지는 플레이어 `설치 ×N`, 적 `적용됨` · `×N/M` · `랩 전용`이다. 최대 스택 카드는 비활성이다. Q/E로 탭을 옮기고 Esc로 닫는다. Lab의 적 진화 카드는 등장 조건 없이 바로 고를 수 있다.
- **증강 떼기**: 적용된 카드에는 `떼기` 버튼이 붙고, 우클릭도 같은 동작이다(비활성 카드 포함). 누를 때마다 가장 최근 스택 하나를 떼며 선택 창은 열린 채 갱신된다. 헤더 `전부 떼기 (N)`는 현재 모드의 증강을 모두 떼고, 탭에는 `이름 · 카드 수 · 적용 수`를 보인다. 적 증강은 `EnemyAugmentRegistry.remove_augment`로 떼며, 붙일 때처럼 이후 스폰부터 적용된다(진화를 떼면 원본 씬으로 돌아옴). 시설 증강은 `PlayerAugmentRegistry.uninstall_augment`로 슬롯을 비우며 슬롯 수는 유지한다.

## 전이

```text
Menu ─(게임 시작)→ World
  │                 ├─ Ship.tree_exited → 1초 대기 → Game Over ─(메인 메뉴)→ Menu
  │                 └─ Esc → 일시정지 ─(계속하기·Esc)→ World
  │                                   ├─(설정)→ 설정 패널 ─(돌아가기·ui_cancel)→ 일시정지
  │                                   └─(메인 메뉴)→ Menu
  └─(설정)→ 설정 패널 (Menu 위 모달) ─(돌아가기·ui_cancel)→ Menu
```

오그먼트 오버레이는 **씬 전환이 아니라** World 위 오버레이다. 오퍼 중 전투는 일시정지하고, 왼쪽 HUD와 전장을 어둡게 덮은 무대에 카드 3장을 나란히 두며 우측 STATUS는 그대로 보여 미리보기에 쓴다. 상세는 [오그먼트](augments.md#ui-요약).

## 공용 UI 테마 (`menus/ui_theme.tres`)

전투 HUD는 아래의 조종석 시각 기준을 따른다. 프레임은 전장보다 낮은 대비로, 글자·상태 게이지·장착/포커스는 읽을 수 있는 밝기로 표시한다.

메뉴 계열 화면(시작화면·설정·일시정지·게임 오버·증강 선택)은 World HUD와 같은 네온 SF 톤을 하나의 `Theme`로 공유한다. 각 화면 루트에 테마를 지정하고, 개별 노드의 `theme_override_*`는 테마로 표현할 수 없는 경우에만 쓴다. World 조종석 HUD는 같은 글자 팔레트와 `LabelSettings`를 쓰며 패널 외형은 승인된 목표 이미지를 따른다.

- 공용 배경 `menus/menu_backdrop.tscn`: 스크롤 `SpaceBackground` + 메뉴 전용 글로우(`glow_intensity` 1.6, HDR 글자에만 걸림) + 비네트 + 화면 모서리 `NeonCornerFrame`. 시작화면·게임 오버가 사용한다.
- 공용 포커스 `menus/ui_focus.gd`(`UiFocus`): 세로 목록 위/아래 순환 연결, 포커스를 잃었을 때 복구 판정. 모든 메뉴 계열 화면이 사용한다.
- 화면 전환은 0.4초 페이드인 / 0.2초 페이드아웃(시작화면·게임 오버).

| 항목 | 값 |
|---|---|
| 기본 폰트 | Mulmaru 12px. 원본 픽셀 격자가 12px이므로 크기는 12의 배수(12·24·36)만 써서 2배(1280×720)·3배(1920×1080) 화면 모두 선명하게 유지한다. 메뉴·오버레이는 `fonts/Mulmaru.ttf`(안티앨리어싱·힌팅 끔)를, World 조종석 HUD는 같은 글꼴의 `fonts/Mulmaru_hud.ttf`(회색 안티앨리어싱·라이트 힌팅·서브픽셀 배치·밉맵)를 쓴다 |
| 패널 바탕 | 남색 `(0.018, 0.035, 0.075)`, 불투명도 0.96 · 테두리 1px 청색 `(0.1, 0.65, 0.95)` · 안쪽 여백 14px + 바깥쪽 `NeonCornerFrame` 브래킷 |
| 본문 글자 | 연청백 `(0.82, 0.92, 1.0)` · 보조 글자 `(0.45, 0.62, 0.8)` |
| 강조(포커스) | 시안 `(0.35, 0.88, 1.0)` — 왼쪽 3px 강조선 + 옅은 시안 바탕 |
| 비활성 | 회청색 `(0.3, 0.38, 0.5)` |
| 타입 변형 | `TitleLabel`(36px, HDR 시안 + 글로우) · `GameOverTitle`(36px, HDR 적분홍) · `SubtitleLabel`(12px 자간 2 청색) · `RecordLabel`(12px 자간 2 HDR 금색) · `HeaderLabel`(24px) · `HintLabel`(12px 보조색) · `MainMenuButton`(24px 메인 메뉴 항목) · `SettingsRow`/`SettingsRowFocused`(설정 행 바탕) · `SettingsToggle`(켬 상태는 시안 채움, 자체 포커스 표시 없음) |

포커스와 마우스 호버는 같은 모습이다. 마우스가 항목 위에 올라가면 그 항목이 포커스를 가져간다.

## Menu (`menus/menu.tscn`)

- 타이틀 표시: **갤럭시 메이헴**(36px, 네온 글로우). 그 위에 보조 문구 `PROJECT AFTERBURN`, 아래에 1px 청색 구분선을 둔다. 타이틀 밝기는 ±8%로 천천히 맥동한다.
- 배경: 공용 배경 `menu_backdrop.tscn`. 진입 시 0.4초 페이드인.
- 메뉴 항목(세로): **게임 시작 · 설정 · 종료**. 진입 시 `게임 시작`에 포커스. 위/아래로 이동하고 끝에서 반대쪽으로 순환하며 `ui_accept`로 결정한다. 웹 빌드에서는 `종료`를 숨긴다.
- 포커스를 잃은 상태에서 방향·확인 입력이 오면 기본 항목(`게임 시작`, 설정에서 돌아온 직후엔 `설정`)에 포커스를 복구한다.
- 메뉴 진입 시 World를 비동기로 미리 로드한다. `게임 시작`을 결정하면 메뉴 입력을 잠그고, 로딩이 끝나면 0.2초 페이드아웃 후 전환한다. 전환은 검은 페이드 뒤에서 World를 먼저 트리에 붙이고 메뉴를 지우는 **수동 교체**다. `change_scene_to_packed`는 메뉴를 먼저 지워 World 인스턴스가 끝날 때까지(약 0.3초) 기본 배경색(회색) 빈 프레임이 보이므로 쓰지 않는다. 대기 중에는 메뉴 아래에 `게임 준비 중... N%`를 표시한다. 로딩 실패 시 `게임 로딩 실패`를 표시하고 시작 항목을 비활성화한다. World 로딩이 끝나면 오퍼 카드 폴더(`resources/player_augments`, `resources/enemy_augments`)도 메뉴 뒤에서 한 파일씩 순서대로 미리 읽어, World `_ready`의 폴더 스캔이 캐시만 읽게 한다(동시 스레드 로드는 씬 로드와 의존 리소스를 공유해 파싱 오류를 내므로 금지). 프로세스당 첫 시작에는 페이드아웃이 끝난 검은 화면 뒤에서 `effects/shader_warmup.gd`가 오프스크린 SubViewport(HDR 전장용 · SDR 오버레이용)에 함선·일반 적·엘리트 외형, 배경, 폭발, 탄 종류별 배치, 카드를 3프레임 그려 셰이더·파티클 파이프라인을 미리 컴파일한다. 이 워밍업이 없으면 World 첫 프레임이 약 180ms(엔진 파티클 170ms·궤도 링 90ms·HDR 글로우 40ms가 겹침), 런 중 첫 탄·엘리트·오퍼 프레임이 각 30~60ms 멈춘다. 두 번째 시작부터는 건너뛴다.
- 하단: 왼쪽 `최고 점수 000000`(현재 런 기록, 저장되지 않음), 오른쪽 조작 안내 `↑↓ 이동 · Enter 결정`.

## 설정 (`menus/settings_menu.tscn`)

Menu와 일시정지 위에 뜨는 모달 패널이다(씬 전환 아님). 같은 씬을 시작화면(`Menu`의 자식)과 World(루트 자식, 화면 전체)에서 쓴다. 열려 있는 동안 아래 화면의 타이틀·항목은 숨기고 배경만 어둡게 덮어 보이며, 마우스 입력을 막는다.

| 행 | 조작 | 적용 |
|---|---|---|
| 마스터 볼륨 | 좌/우 5% 단위(슬라이더 `step` 0.05), 0–100% | `Master` 버스. 0%면 음소거 |
| 음악 | 〃 | `Music` 버스 |
| 효과음 | 〃 | `SFX` 버스 |
| 전체 화면 | `ui_accept`·좌/우로 켬/끔 전환 | 창 모드 전환 (headless에서는 저장만) |
| 전투 이벤트 로그 | `ui_accept`·좌/우로 켬/끔 전환 | 기본 켬, 전투 알림만 제어 |
| 돌아가기 | `ui_accept` | 패널 닫기 |

- 열면 첫 행(마스터 볼륨)에 포커스. 위/아래로 행 이동(끝에서 순환), 포커스된 행은 `SettingsRowFocused` 바탕으로 강조한다. 볼륨 행은 오른쪽에 `N%`를 표시한다.
- `ui_cancel`(Esc) 또는 `돌아가기`로 닫고, 닫으면 연 화면의 `설정` 항목으로 포커스를 돌려준다. 열려 있는 동안 아래 화면 항목은 포커스를 받지 않는다. 일시정지에서 연 경우 Esc는 설정만 닫고 일시정지는 유지한다.
- 변경은 즉시 적용하고 마지막 변경 0.25초 뒤 저장한다.

## 설정 저장 (`GameSettings`, `game_settings.gd`)

- 오토로드 노드 `UserSettings`로 하나만 띄우고 코드에서는 `GameSettings.instance`로 접근한다. 오토로드 전역 이름은 `--script` 테스트에서 컴파일되지 않으므로 쓰지 않는다.
- 파일: `user://settings.cfg`. 키: `audio/master_volume` · `audio/music_volume` · `audio/sfx_volume`(0.0–1.0, 값이 없으면 버스 레이아웃의 현재 볼륨) · `display/fullscreen`(기본 false) · `display/combat_event_log`(기본 true).
- 게임 시작 시 한 번 읽어 버스 볼륨·창 모드를 적용한다. 메뉴의 설정 패널과 World의 일시정지 설정은 모두 `GameSettings`를 통해 읽고 쓰며, 한쪽에서 바꾸면 다른 쪽 표시도 따라간다.
- 저장 실패는 경고만 남기고 게임을 막지 않는다. 테스트·캡처 스크립트는 `GameSettings.instance.save_enabled = false`로 사용자 설정 파일을 건드리지 않는다.

## World (`world.tscn` / `world_shell.gd`)

### 조종석 HUD · 시각 기준

[승인된 절대목표 이미지](references/pilot-visor-target.png)를 외형 기준으로 삼는다. 상단 캐노피, 불투명한 측면 계기판, 안쪽으로 기울어진 하단 콘솔, 남색 금속·청록 테두리·황색 표시등의 비례와 질감을 유지한다. 정보의 세부 배치는 바뀔 수 있지만 단순 직사각형 세 칸으로 되돌리지 않는다. 글자·수치·슬롯은 이미지에 구워 넣지 않고 실제 게임 상태로 표시한다.

640×360 기준 좌우 150px와 중앙 340×360 전장을 쓴다. 화면은 기준 비율을 보존한다. 전장 아래 226px부터 양쪽 경계가 안쪽으로 기울어 하단에는 각각 76px의 UI 영역을 확보한다. 상단 캐노피의 24×22px 사선도 경계에 포함한다. 클램프는 피탄점 기준이다. 기체 원점의 피탄점(반지름 3px)이 경계 안쪽 1px 여백(클램프 여백 4px)을 지키면 되고, 기체 비주얼은 프레임 밑으로 들어갈 수 있다. 출격 중에는 기존처럼 클램프를 해제한다. Lab은 기존 직사각형 전장을 유지하며 같은 4px 여백을 쓴다.

전장 논리는 340×360 레인이지만 렌더링은 좌우 16px씩(`CockpitGeometry.FIELD_BLEED`) 더 그린다. 프레임 아트의 개구부가 콘솔 어깨(y 232~290) 구간에서 레인보다 넓어 레인 끝이 검은 띠로 드러났기 때문이다. `PlayfieldViewport`는 372×360으로 그리고 2D 크기 오버라이드로 가시 영역을 340×360에 고정하며, 전역 캔버스 변환으로 레인 원점을 16px 옮긴다. 출격으로 패널이 전개되는 동안(0~1.25초)은 bleed를 150px로 올려 640px 전체 폭을 그려 아직 덮이지 않은 양옆에 검은 바탕 대신 우주가 보이게 하고, 모든 패널이 정착하면 16px로 되돌린다. bleed 변경은 배경 사각형만 늘이고 성운·실루엣 레이어를 다시 만들지 않아 스크롤이 끊기지 않는다. 적·탄·스폰·클램프·오프스크린 판정은 모두 340 레인 기준 그대로이고, `SpaceBackground`의 `bleed`만 별밭·성운 바탕·궤도 링 사각형을 양옆으로 넓힌다. 궤도 링 셰이더는 `rect_size`·`rect_offset`으로 레인 좌표를 유지한다. 아트 개구부와 클램프선의 차이는 아트 수정 가능성을 두고 보류한다.

- 좌측 상단: 점수. 좌측 측면: STAGE/엘리트 진행. 좌측 하단: 실드·충전 및 XP, 준비되면 `AUGMENT READY [C]`. 실드 글자·호형 게이지·충전 표시와 XP 글자·막대는 모두 하단 콘솔을 따라 시계 방향 10°로 기울인다. 평상시 XP는 `XP 현재 / 필요`로 간결하게 표시한다.
- 우측 측면: 위쪽은 5→15 범용 시설(5열, 최대 3행의 변을 공유하는 벌집; 기본 5칸은 첫 행만 표시)과 호버 툴팁의 시설 설명, 아래쪽은 무기 베이 3→4개를 수평 한 줄로 배치한다. 시설·베이가 칸을 넘거나 금속 프레임에 걸리지 않도록 내부 여백을 둔다. 시설 칸은 가로 20px·아이콘 12px로 표시한다. 무기 베이는 기본 32px, 4베이 확장 시 26px로 표시한다. 우측 하단에는 24px 장착 모듈 벌집과 44px 선택 무기·설명을 반시계 방향 7°로 기울여 배치한다. 기존 미리보기·호버·교체 동작을 유지하며 각 정보는 소속 패널과 함께 전개된다.
- 볼륨 슬라이더는 전투 HUD에서 제거한다. Esc → 설정의 마스터 볼륨을 사용한다.
- HUD의 글자가 길어져도 전장과 프레임은 움직이지 않는다. 무기 설명은 하단 1줄 이름과 전체 내용을 보여 주는 툴팁으로 표시한다. 시설 설명은 해당 슬롯의 호버 툴팁으로 표시한다. 프레임 바깥과 측면은 UI이고 배경이 비쳐 전장으로 오인되지 않는다.

### 해상도 분리

중앙 전장만 저해상도 픽셀이고 좌우 조종석은 창 해상도로 그린다. 전장은 `PlayfieldViewport`가 논리 340×360(렌더링은 좌우 bleed 포함 372×360)으로 그린 뒤 NEAREST로 정수 배 확대하며 2D MSAA를 켜지 않는다. 좌우 패널은 LINEAR 필터와 HUD 폰트(`fonts/Mulmaru_hud.ttf`: 회색 안티앨리어싱·라이트 힌팅·서브픽셀 배치·밉맵)를 쓰고, 루트 뷰포트의 2D MSAA(2×)로 호형 게이지·회전된 막대의 가장자리를 다듬는다. 10°·7° 기울인 계기 글씨가 계단 없이 읽혀야 하며 프레임 텍스처는 그대로 LINEAR다. HUD 전용 `LabelSettings`(`default`·`title`·`hex_module`·`ship_panel_detail`)가 이 폰트를 가리키고, 메뉴·일시정지·강화 오버레이는 기존 픽셀 폰트와 정수 px 규칙을 유지한다. 전장 안의 상시 글자는 두지 않는다. 예외는 아래의 짧은 전투 이벤트 로그다.

### 패널 전개와 점등

출격 시퀀스의 동일한 게임 시간축을 사용한다. 좌우 각각 상단 캐노피·측면·하단 콘솔을 독립된 6개 조각으로 전개한다. 0~1.25초에 바깥에서 순차 진입, 0.48~1.69초에 전원 점멸·화면 스캔, 1.8초 입력 해제 전에 모두 정착한다. 진입 중 패널 뒤 양옆은 전장을 전체 폭으로 그려 우주가 보이며(「해상도 분리」의 bleed), 1.25초에 정착과 함께 전장 폭이 원래대로 돌아간다. 2.6초에 적 생성이 시작되는 기존 출격 시간을 늘리지 않는다. Esc 일시정지 중 전개와 점등도 멈추며 재개 시 이어진다. 매 런 진입마다 재생하고, 테스트에서 출격하지 않은 씬은 완성 상태로 표시한다.

첫 출격의 프레임 점등 셰이더도 기존 HDR 워밍업에 포함한다. 프레임 텍스처는 `assets/ui/cockpit/pilot_visor_frame.png`, 표시 내용은 실제 HUD 노드다. 원본 목표 이미지는 변경하지 않는다.

### 조종석 표시등 제어

- 원본 프레임은 유지하고, `pilot_visor_lamps_mask.png`로 노란 표시등 9곳과 따뜻한 빛 번짐만 분리한다. 마스크 밖 금속·청록 라인·투명 영역에는 색상/밝기 제어를 적용하지 않는다. 이미지 생성 도구를 사용하지 않는다.
- 평상시에는 원본 노란색과 밝기를 그대로 표시한다. `CockpitHud.set_indicator_style(color, blend, brightness)`로 전체 표시등의 색상 혼합량(0=원본, 1=지정색)과 밝기(0~2)를 제어한다. 개별 표시등 제어는 이번 범위에 포함하지 않는다.
- 실제 `ShieldComponent.shield_changed` 이벤트와 초기 실드 값을 읽는다. 실드가 양수에서 0이 되면 표시등 9개가 0.16초 동안 밝은 연적색(밝기 1.65)에서 빨강(1.0)으로 감쇠한 뒤, 기존 0.8초 주기 빨간 점멸(1.0↔0.18)로 이어진다. 0에서 1칸 이상 회복하면 초록색(밝기 1.25)이 0.12초 유지되고 0.43초 동안 원본 노란색·밝기 1.0으로 부드럽게 복귀한다. 회복 중 다시 소진되면 즉시 파손 연출로 교체하며 추가 회복·부분 감소는 연출을 재시작하지 않는다. 초기 실드 0(최대 0 포함)은 파손 섬광 없이 빨간 점멸만 시작하고, 정상 출격에는 회복 점등을 재생하지 않는다. 충전 진행률만으로 경고를 해제하지 않는다.
- 게임 시간 `delta`로 점멸을 진행하여 ESC·증강 선택 등 모든 일시정지에 함께 멈추고 재개한다. 출격의 기존 패널 전개·전원 연출은 그 위에 그대로 적용한다. 함선 제거 시 점멸 처리를 멈추며, 새 런은 새 실드 상태로 초기화한다.
- **실드 게이지 피격 반응** (등급 정의는 [플레이어 · 피격 연출](player.md#피격-연출)): 견딜만한 피격은 꺼지는 호형 칸만 흰색 (1.0, 1.0, 1.0)에서 0.25초 동안 꺼진 색 (0.06, 0.14, 0.22)으로 감쇠한다. 위험한 피격은 12칸 전체가 붉은색 (0.95, 0.25, 0.25)으로 0.3초 번쩍인 뒤 꺼진 색이 된다. 실드 0 동안 게이지는 맥동하지 않으며 맥동은 표시등·전장 가장자리가 맡는다. 회복 칸은 기존대로 즉시 켜진다. 게임 시간으로 진행해 일시정지에 멈춘다.
- **패널 흔들림**: 피격에 전장은 그대로 두고 조종석 패널 여섯 장(좌우 × 캐노피·콘솔·윙)과 그 위 계기가 각자 흔들린다. 패널마다 무게가 다르다: 캐노피는 1px·0.15초·40Hz로 가볍게 떨고(주로 가로), 콘솔은 2px·0.25초·24Hz로 0.03초 늦게 충격 방향으로 밀리며, 윙은 3px·0.4초·14Hz로 가장 늦게 가장 오래 주로 세로로 울린다. 변위는 `진폭 × (1 − t/길이)² × sin(2π·주파수·t)`다. 탄이 온 쪽 패널이 먼저·100%로 흔들리고 반대쪽은 0.05초 뒤 70%다(`impact_direction`의 x 부호, 거의 세로 피격이면 양쪽 동시 100%). 위험한 피격은 진폭 ×1.8이고 표시등 `power`를 0.06초 동안 0.2로 떨어뜨려 전력 딥을 낸다. 흔들림 중 새 피격은 흔들림을 처음부터 다시 시작한다. 패널 사이가 벌어지지 않도록 각 패널 폴리곤을 이웃 이음새와 전장 쪽으로 3px 넓혀 겹쳐 그리며, 창 바깥 가장자리는 넓히지 않는다. 출격 전개 위치와 흔들림 변위는 더해지고, 게임 시간이라 일시정지에 멈춘다. 검증: `tests/player_hit_feedback_test.gd`(패널 흔들림 방향·지연·복귀, 전력 딥, 게이지 섬광)와 기존 조종석·표시등·HUD 안정성 회귀.
- 검증: `tests/cockpit_indicator_test.gd`에서 초기 노랑·실드 소진·부분 회복·반복 피격·일시정지·색상 API를 확인한다. 창 모드에서는 실제 셰이더의 빨강·감광과 마스크 밖 픽셀 보존도 검사한다(반투명 경계의 GPU 8비트 반올림 1단계 허용). 표시등·기존 조종석·HUD 해상도 회귀 및 D3D12 렌더 검증을 통과했다. 파손·회복 추가 후 조종석·표시등·로그 회귀 3개를 통과했으며 회복 중 재피격·일시정지·초기 실드 0과 파손/회복 렌더의 마스크 밖 보존을 확인했다.

### 전투 이벤트 로그

- 전장 좌측 상단(640×360 화면의 x=178, y=28)에 배경 박스 없는 청록색 11px HUD 글자를 기본 불투명도 0.82로 표시한다. 곡면 표시를 위한 HUD 폰트 예외이며 3배 크기 오프스크린 렌더로 가장자리를 보존한다. 폭 180px, 줄 높이 14px, 전투 중 최대 3줄(출격 중에는 5줄, 아래 「출격 부팅 로그」)이며 마우스 입력을 가로채지 않는다. 줄은 상자 바닥부터 쌓이고 상자 높이는 `줄 수 × 14 + 6`px다.
- 알림 영역에만 약한 배럴 왜곡(0.035)과 수직 곡률(0.045)을 적용해 곡면 유리 투영 느낌을 준다. 글자 주변에는 좁고 약한 청록 잔광을 두고, 새 알림 때 0.45초 동안 좌→우 스캔 빛이 한 번 지나간다. 배경·탄·함선에는 왜곡을 적용하지 않으며 연출 시간은 일시정지와 함께 멈춘다. 알림이 없거나 설정을 끄면 오프스크린 렌더를 중지한다. 다 흐려진 고정 줄만 남아 움직이는 것(슬라이드·스캔·페이드·상자 크기 변경)이 없으면 마지막 프레임을 한 번 그려 둔 채 오프스크린 렌더와 매 프레임 처리를 멈추고, 새 알림·해제가 오면 다시 켠다.
- 새 메시지는 아래에서 0.18초 동안 올라오며 나타나고 기존 줄도 위로 이동한다. 완성된 문장을 즉시 보여 주며 타이핑·문자 해독 연출은 없다. 각 줄은 게임 시간 2.8초 수명이며 마지막 0.6초에 사라진다. 새 메시지가 기존 수명을 연장하지 않는다. 줄 수를 넘는 메시지는 고정 줄을 제외한 가장 오래된 줄을 제거한다.
- **고정 줄**: 지나간 사건이 아니라 지금 계속되는 상태를 알리는 줄은 수명 없이 상태가 풀릴 때까지 남는다. 현재는 `AUGMENT READY [C]` 하나다. 고정 줄은 상자 맨 윗줄을 차지하고 그 자리에서 바로 페이드인한다(아래에서 올라오지 않음). 일반 알림은 그 아래 남은 줄에서 바닥부터 쌓이므로 전투 중 일반 알림은 2줄이 된다. 고정 줄은 어떤 경우에도 일반 알림이 쓸 줄을 최소 1줄 남긴다. 등장 후 2.8초 동안은 일반 줄과 같은 불투명도 0.82로 보이고, 2.2~2.8초에 0.45로 낮아져 이미 읽은 알림으로 물러난다. 준비 상태가 풀리면(증강 획득으로 XP 부족, 탄소거 보상 시작) 그 자리에서 0.6초 동안 사라진다. 사라지는 도중 다시 준비되면 스캔 없이 다시 밝아지고, 다 사라진 뒤 다시 준비되면 새 고정 줄로 다시 알린다. 탄소거 보상 중에는 C 입력이 잠기므로 고정 줄을 내리고, 보상이 끝나 준비 상태가 돌아오면 다시 알린다.
- 실드가 양수에서 0이 되면 `SHIELD LOST`, 0에서 양수로 회복되면 `SHIELD ONLINE`, 증강 준비 상태가 false→true이면 `AUGMENT READY [C]`를 고정 줄로 출력한다. 런 시작의 정상 실드와 단순 충전 진행, 일부 실드 감소·추가 회복은 알리지 않는다. 증강 준비 판정은 기존 진행 HUD와 공유하여 탄소거 보상 중에는 출력하지 않는다.
- 실드 파괴 줄은 처음 0.35초 붉게 강조한 뒤 청록색이 된다. 나머지는 청록색이다. 현재 보이는 같은 이벤트는 중복 추가하지 않는다. 일시정지·오퍼 중에는 수명과 이동도 멈춘다.
- **출격 부팅 로그**: 출격 시작(`launch_started`)에 창을 5줄(높이 76px)로 넓히고, 출격 시간축에 맞춰 아래 10줄을 차례로 출력한다. 각 줄의 수명은 1.5초로 짧아 전투 알림보다 빨리 흘러가며, 여섯 번째 줄부터는 가장 오래된 줄을 밀어내 글이 창을 지나가는 모양이 된다. 점화 전후는 0.1~0.2초 간격으로 몰아치고 정착 구간은 0.35~0.45초 간격으로 느려진다. `IGNITION`만 실드 파손처럼 처음 0.35초 붉게 강조한다. 마지막 **출격 하이라이트** 줄은 밝은 백청색(0.93, 1.0, 1.0)에 수명 3.5초로, 앞 줄들이 모두 빠진 뒤 약 2.4초 동안 홀로 남아 여운을 준다. 출격이 끝나면(2.6초) 3줄 복귀를 예약하고, 남은 줄이 3줄 이하로 줄어든 순간 줄 위치를 0.18초 슬라이드로 올린 뒤 상자를 48px로 줄인다. 그동안 들어오는 전투 알림은 넓은 창에 그대로 쌓인다. 일시정지에는 출격 시간축이 멈추므로 출력도 멈춘다. 설정을 끄면 부팅 로그도 출력하지 않으며 독립 `gameplay.tscn`·Lab에는 로그 자체가 없다.

- 구현: `menus/combat_event_log.gd`, `world_shell.gd`, `GameSettings`, 설정 모달. `tests/combat_event_log_test.gd`에서 이벤트 연결·3줄 제한·중복 억제·동시 발생 줄 간격·수명·일시정지·옵션 전환과 출격 부팅 로그(5줄 확장·시각별 출력·밀어내기·1.5초 수명·종료 후 지연 축소·설정 꺼짐)를 검증했다. 설정·조종석·일시정지·HUD 배치 회귀를 포함한 관련 7개 테스트와 D3D12 로그/설정창 캡처 확인을 통과했다. 곡면 연출 변경 후 로그 회귀·스캔 일시정지·빈 로그 렌더 중지와 실제 글자 판독성도 재확인했다. 고정 줄: 같은 테스트에서 맨 윗줄 고정·밀어내기 제외·일반 알림 2줄 제한·2.8초 뒤 0.45 감광·정지 시 매 프레임 처리 중지·해제 페이드·페이드 중 재준비 시 스캔 없는 복귀·설정 재활성화 시 재표시를 검증했다. 창 모드(D3D12)에서는 정지한 고정 줄이 마지막 프레임으로 계속 보이고 오프스크린 렌더를 다시 그리지 않는지 픽셀 비교로 확인했다.

### 런 시작 · 출격 시퀀스 (`effects/launch_sequence.gd`, `LaunchSequence`)

런의 첫 2.6초는 플레이가 아니라 **출격**이다. 함선이 화면 아래에서 애프터버너를 켜고 치고 올라오며, 별이 가속해 선으로 늘어나고, 먹먹하던 음악이 열린다. 목적은 "빠르다"는 감각을 첫 화면에서 몸으로 주는 것이다. 동작은 게임플레이 시간으로 계산하며 입력 잠금 동안 Esc 일시정지는 그대로 된다.

| 구간 | 시각 | 함선 | 배경 (`SpaceBackground.speed_scale`) | 소리 |
|---|---|---|---|---|
| 점화 | 0 ~ 0.5초 | 화면 아래 40px에 정지(`y = 전장 높이 + 40`), 이동 입력·클램프·무기 발사 잠금(무기 로드아웃 `PROCESS_MODE_DISABLED`), 엔진 화염이 커지기 시작 | 0 → 0.3 (별이 겨우 움직임) | 음악 먹먹함 유지(로우패스 500Hz) |
| 연소 | 0.5 ~ 1.6초 | 0.3초부터 홈 위치(World의 중앙 `(170, 216)`, 독립 Gameplay 씬은 `(100, 216)`)까지 ease-out cubic로 상승, 앵커 ±2px 진동, 엔진 화염 세로 3배·`speed_scale` 2.5 | 0.3 → 7.0 (가까운 별층 1120px/s), 스트릭 선 표시 | 0.3초에 `sounds/launch_burn.wav`(합성 엔진 굉음, SFX 버스) 1회. 0.6 ~ 1.4초에 로우패스가 500 → 20500Hz로 열림 |
| 정착 | 1.6 ~ 2.6초 | 1.8초에 입력·클램프·무기 발사 해제(이후 함선은 플레이어 것), 화염·진동 원복 | 7.0 → 1.0 (순항) ease-in | — |
| 종료 | 2.6초 | 함선은 플레이어가 옮긴 위치를 유지(홈으로 되돌리지 않음). `launch_finished` → `EncounterDirector.start_sequence()` (씬의 Director는 `autostart = false`) | 순항 | — |

- 시작 조건은 Director와 같다. `LaunchSequence`가 `_ready`에서 `current_scene`이 있을 때만 스스로 재생하므로 테스트에서 씬을 붙여도 돌지 않고, `play()`로 직접 재생한다. 재생 중이 아니면 함선·입력·Director는 지금까지와 같다.
- 음악 먹먹함: `Music` 버스의 `AudioEffectLowPassFilter`(버스 레이아웃에 상주, 기본 열림). 시작화면이 열릴 때 닫고(`LaunchSequence.set_music_muffled(true)`), 출격의 연소 구간에서 연다. 일시정지·게임 오버에서 메뉴로 돌아가면 다시 닫힌다.
- 출격 중 전장 좌상단의 전투 이벤트 로그가 5줄로 넓어지며 함선 부팅 로그 10줄을 흘려보낸다(「전투 이벤트 로그 · 출격 부팅 로그」). 이 표의 시각을 바꾸면 그 표의 문구 시각도 함께 맞춘다.
- 건너뛰기는 없다(2.6초). 체감이 길어지면 이 표의 시각만 줄인다. 출격 중 왼쪽 HUD의 Threat 표시는 Director가 아직 시작 전이라 타이머 모드(`MM:SS`)로 보이다가 시작과 함께 `STAGE`로 바뀐다.

완료 조건·검증: 재생 전 함선·입력·Director가 기존 상태, 재생 시작에 함선이 화면 밖·입력 잠금·음악 먹먹함, 연소 중 `speed_scale` 3 이상과 스트릭, 1.5초에 로우패스가 열리는 중, 1.8초 이후 입력 해제(해제 시점에 홈 위치), 종료 시 해제 뒤 플레이어가 옮긴 위치 유지·순항 속도·Director 실행·`launch_finished` — `tests/launch_sequence_test.gd`.

### 라이프사이클

1. `_ready`: `game_stats.score = 0`, 점수 라벨 연결
2. `Ship.tree_exited`: 1초 대기 후 Game Over 씬으로 이동
3. 오그먼트 오퍼 중: `get_tree().paused = true` (오버레이 `PROCESS_MODE_ALWAYS`)
4. **ESC** (`world_shell.gd`): 수동 일시정지 토글 · 일시정지 메뉴(`PauseOverlay`) 표시. 오그먼트 등 **다른 시스템이 건 pause** 중에는 ESC로 해제하지 않음

### 일시정지 (`menus/pause_menu.tscn`, World `Layout/Playfield/PauseOverlay`)

- 중앙 전장(340×360)만 어둡게 덮고 좌우 HUD는 그대로 보인다. `PAUSED` 보조 문구 + `일시 정지`(24px) + 구분선 아래에 **계속하기 · 설정 · 메인 메뉴**(`MainMenuButton`), 하단에 `Esc 계속하기` 안내.
- 열면 `계속하기`에 포커스. 위/아래 순환, `ui_accept` 결정. `Layout`이 일시정지 시 멈추므로 메뉴 자체는 `PROCESS_MODE_ALWAYS`로 입력을 받는다.
- `계속하기`·Esc → 재개. `설정` → 설정 패널(일시정지 유지). `메인 메뉴` → 일시정지 해제 후 Menu로 전환하며 진행 중 점수는 최고 점수에 반영하지 않는다.

## Game Over (`menus/game_over.tscn`)

- 공용 배경 위에 `MISSION FAILED` 보조 문구 + **게임 오버**(`GameOverTitle`) + 점수 패널.
- 점수 패널: `점수`(24px 6자리) · `최고 점수`(12px 보조색 6자리). `score > highscore`이면 highscore를 갱신하고 `NEW RECORD`(금색)를 표시한다.
- 항목은 **메인 메뉴** 하나이며 진입 시 포커스. `ui_accept` → 0.2초 페이드아웃 후 Menu.

## 오그먼트 오버레이 플로우

1. 적 사망 시 경험치 오브 드롭 → 플레이어 접촉 시 경험치 획득
2. XP가 요구량을 채워도 **자동으로 열리지 않음**. `open_augment_offer`(**C**)로 PLAYER 오퍼 요청 · 오퍼 UI가 이미 열려 있으면 XP 미소모
3. 시퀀스 ELITE 스텝 → 다음 Threat 엘리트 1기 소환. 현재 Threat는 유지하고 일반 Encounter와 시퀀스는 대기한다. Director 미사용 시에만 60초 타이머로 요청한다.
4. 엘리트 처치 → pause 없이 화면 안 `enemy_projectiles`를 탄 위치의 XP 1 오브로 변환(화면 밖은 XP 없이 소거). 기존 XP와 엘리트 확정 드롭도 함께 플레이어에게 강제 흡수하며 이 동안 `C` 플레이어 오퍼 입력을 잠금
5. 모든 XP의 실제 정산 완료 → Threat 상승 → ENEMY 오퍼 요청. pause는 오퍼가 연다
6. `AugmentOfferController.request_offer(type)` → `offer_started(type)` → pause. 강화 분기점 인트로는 PLAYER 청색 / ENEMY 적색 테마로 구분
7. PLAYER 오퍼는 상단 3지선다와 하단 `범용 슬롯 +1`을 함께 표시. `FACILITY_EFFECT`는 우측 STATUS 범용 육각 슬롯의 같은 tag·빈 칸 미리보기, 무기 Kind는 병기 배치·모듈 레벨 미리보기를 표시하되 하단 슬롯 확장 버튼은 바꾸지 않음
8. 시설 카드 → 범용 빈 슬롯 설치(가득 차면 전체 슬롯 교체 모달). 무기 Kind(획득·모듈 강화) → 로드아웃에 직접 적용(만석 획득은 베이 교체 UI). `범용 슬롯 +1`은 Kind와 무관하게 선택 가능(포커스/호버 → 다음 육각 칸 점멸, 선택 → 용량 +1; 시작 5, 최대 15면 비활성)
9. ENEMY 오퍼는 기존 3지선다 선택 → registry 반영
10. **PLAYER 오퍼 종료 직후** 함선 주변 `enemy_projectiles` 제거 + `augment_resume_burst` VFX (`player_resume_clear_radius` 기본 36)
11. unpause → `offer_completed(type)`. ENEMY 오퍼였다면 게이트를 닫고 시퀀스 진행 재개 (Director 미사용 시에만 일반 스폰·새 60초 타이머 재개)
12. 대기 중인 오퍼가 있으면 deferred로 재요청

## 완료 조건·검증

- 메뉴→플레이→게임 오버→메뉴 흐름이 완료된다.
- 다른 시스템이 소유한 일시정지를 ESC로 해제할 수 없다.
- 방향 입력과 확인만으로 선택·교체를 완료하고 모달 복귀 시 유효 포커스를 복원한다.
- 시작화면·일시정지에서 방향키·Enter·Esc만으로 모든 항목과 설정 열기/닫기에 도달한다. 설정에서 돌아오면 `설정` 항목에 포커스가 있다.
- 일시정지에서 설정을 열고 닫아도 게임은 멈춘 상태를 유지한다.
- 게임 오버에서 최고 점수를 넘으면 `NEW RECORD`가 보이고, Enter로 메인 메뉴로 돌아간다.
- 설정 패널의 볼륨 변경이 해당 버스에 즉시 반영되고, 재실행 후에도 유지된다. 메뉴와 전투 중 설정의 값이 일치한다.
- 시작화면·설정·일시정지·게임 오버가 공용 테마를 사용하고 640×360에서 글자가 잘리거나 겹치지 않는다.
- XP 충족·탄소거 보상·엘리트 게이트로 HUD 글자가 바뀌어도 World 조종석 프레임과 전장의 위치·폭이 변하지 않는다.
- 좌우 조종석 글씨는 HUD 폰트와 LINEAR 필터로 기울어진 상태에서도 계단이 없고, 전장 서브뷰포트는 340×360 NEAREST 확대와 MSAA 없음을 유지한다 (`tests/side_hud_crisp_rendering_test.gd`).
- 시작화면에서 World로 넘어갈 때 검은 페이드 외의 색(기본 배경색 회색)이 한 프레임도 보이지 않는다.

검증 참고: `tests/hud_layout_stability_test.gd` · `tests/pause_smoke_test.gd` · `tests/menu_loading_smoke_test.gd` · `tests/settings_menu_smoke_test.gd` · `tests/game_over_smoke_test.gd` · `tests/master_volume_control_test.gd`. Godot 실행은 `tools/run-godot.cmd`를 사용한다.

조종석 검증: `tests/cockpit_hud_test.gd`에서 6개 패널 전개·일시정지·재출격·아트의 실제 투명 영역 안에 피탄점이 머무는지·피탄 반지름+1px 클램프 여백·전장 bleed(뷰포트 372×360, 가시 영역 340×360, 배경·궤도 링 사각형 확장)·최대 15시설/4베이를 검증한다. 회전된 계기 모서리가 콘솔 유리 안에 들어가는지, 기본 5칸·최대 15칸의 시설 개별 호버와 4베이의 여백, 긴 준비 문구, 정보와 소속 패널의 전개 동행도 확인한다. 기존 HUD·시설 미리보기·무기 포커스·메뉴/설정·출격 회귀와 기본/최대 확장 실제 실행 캡처로 배치와 점등을 확인한다.
