# 전투

## 기획 의도

작은 피격 코어와 일관된 피격·실드 규칙으로 회피의 성공과 실패를 명확히 전달한다. 엘리트 처치 보상은 탄막 회피 구간에서 다음 선택으로 넘어가는 휴지기를 만든다.

## 확정된 현재 동작

## 물리 레이어 이름 (`project.godot`)

| Bit | 이름 |
|-----|------|
| 1 | `player_hurtbox` |
| 2 | `enemy_hurtbox` |
| 3 | `player_projectile` |
| 4 | `enemy_projectile` |

**레이어 3–4는 미사용.** 탄 Hitbox는 대개 layer 0 + hurtbox **mask**로 동작한다.

## 레이어/마스크 실사용

| 액터 | Layer | Mask |
|------|-------|------|
| Player Hurtbox | 1 | default |
| Enemy Hurtbox | 2 | 0 |
| Enemy Hitbox (몸) | 0 | 1 |
| Player Blaster Hitbox | 0 | 2 · damage **10** |
| Player Shotgun Pellet | 0 | 2 · damage **4** × 5발 |
| Curve/Counter 탄 | 0 | 1 |
| Laser RayCast | — | 2 (직접 `hurt.emit`) |

## 데미지 파이프라인

```text
Hitbox.area_entered
  → Hurtbox & not invincible
  → hit_hurtbox + hurtbox.hurt
  → HurtComponent
      → (player) incoming = 1
      → notify_hit (실드 충전 게이지 리셋)
      → 실드에 먼저 피해 적용, 남은 피해만 stats.health -= remaining
  → 생존→사망 전환이면 no_health 1회 → 파괴/점수
```

레이저는 Area 겹침을 쓰지 않고 RayCast + DamageTickTimer로 `hurt`를 직접 보낸다.

`HurtComponent.shield_component`는 플레이어에만 연결돼 있다(적은 null → 기존 동작). **플레이어가 맞는 피해는 항상 1.** 실드는 버퍼 HP라 실드 0일 때만 선체가 깎인다. 모든 피격 후 기본 0.6초 무적이며, 충격 분산 골격은 선체 피격 무적시간을 1.0초 늘려 총 1.6초로 만든다.

### 탄환 기본 종류 확장

#### 확정된 1차 구현 · 비교 실험용

2026-09-16: 원탄·쌀탄·대형 구탄과 직선·파동 이동을 조합하는 공통 적탄 및 `projectiles/bullet_lab.tscn` 비교 장면을 구현했다. 아래 1차 실험 수치를 사용한다. 최초 구현은 비교 시험용이었으며 현재 Drone은 BarrageSequence와 공통 탄을 사용한다. 선회·가감속·호밍과 곡선 레이저도 아래 구현 완료 절을 따른다. 새 적탄의 이동/예측은 동일한 시간 함수로 계산하고, 위협도는 궤적 표본과 탄별 판정 외접 반지름 + 6px 여유를 사용한다. 기존 탄은 기존 직선 예측을 유지한다.

시험 장면은 외형·이동·발사 패턴 선택, 일시정지·재시작·판정 표시·탄소거를 제공한다. 방향키와 Enter로 UI를 조작하고 WASD로 시험 기체를 움직인다. 시험 기체 피격은 횟수를 세며 0.6초 무적을 적용한다. 실제 성장/체력 소모를 대신하는 비교용 기체다.

- 부채꼴 5발/48°, 링 16발, 아래 단발, 대각선 단발을 선택한다. 모든 비교는 속도 95px/s·주기 0.9초다. 설정 변경/초기화는 기존 탄·피격·소거 횟수를 지우고 자동 재생한다. 기존 기본탄에서 파동을 선택하면 새 원탄으로 전환한다.
- 일시정지는 탄·발사·기체·무적 시간·계측을 함께 멈추며 메뉴는 계속 조작할 수 있다. 시험 장면의 탄소거는 제거한 발 수만 표시한다. 실제 XP 전환은 기존 `BulletCancelRewardController` 계약을 사용하며 별도 회귀 테스트로 검증한다.
- `foundation_bullet.tscn`의 `appearance`와 `behavior`에 `resources/projectiles/`의 설정을 조합한다. `BulletAppearance`가 기하 코어·원/캡슐 판정을, `BulletBehavior`가 이동과 탄별 변화를 제공한다. Motion 호환 입력은 제거했으며 일반 탄에는 Behavior를 반드시 지정한다. 발사 연결은 기존 `launch(direction, speed)`다.
- 탄은 설정을 복제해 사용하고 판정을 매번 새로 만든다. 루트를 물리 프레임에서 한 번만 갱신하며 원점·그림·판정 중심이 일치한다. 기본 코어는 코드로 그린 기하 형태이고 입자 트레일은 사용하지 않는다.
- 파동 진폭은 0~128px, 주기는 0.1초 이상, 수명은 양수여야 한다. 크기/방향/속도는 유한값이어야 하며 0 방향·음수 속도·잘못된 설정은 오류와 함께 탄을 제거한다. 속도 0은 허용하지만 수명은 흐른다. 기본 수명은 8초다.
- 실제 이동·판정은 기본 95px/s에서 검증했다. 임의의 고속/급격한 파동 조합에 대한 연속 충돌 검출은 제공하지 않는다. 고속 범위 확대 전 충돌 누락 검증이 필요하다.
- 신규 탄의 예측은 최대 50ms, 파동 한 주기당 최소 24구간으로 표본화하고 남은 수명과 화면 이탈에서 끝낸다. 궤적 구간 수와 무관하게 밀도는 한 발로 센다. 정지한 신규 탄도 공간 점유에 포함한다. 캡슐은 외접 원을 쓰므로 위협도는 보수적 근사이며 실제 피격 판정이 아니다.
- 새 탄의 화면 밖 제거는 코어 크기만큼 확장한 뷰포트를 사용한다. 한 번 진입한 뒤 이 경계를 벗어나면 제거하고 처음부터 화면 밖인 탄도 수명으로 정리한다.

2026-09-15 조사에 따른 **적탄의 기본 어휘 확장**이다. 아래 후보·수치는 비교 실험 기준이며 실제 Encounter 밸런스 확정값은 아니다. 플레이어 무기 확장은 별도 검토한다.

#### 탄환 렌더링 최적화 · 구현 완료

- 적용 대상은 새 `FoundationBullet` 3종과 `CurvedLaser`, 비교 장면이다. 기존 적의 탄종 배정은 유지한다.
- 일반 탄은 같은 외형끼리 MultiMesh로 렌더링하고 곡선 레이저는 리본 메시를 모아서 그린다. 코어·글로우 색/폭과 곡선 표본, 발사·피격·소거 계약은 보존한다.
- 판정 표시는 엔진 전역 디버그와 중복되지 않게 한다. 캡슐/원 판정의 표시도 묶어서 그리며, 실제 충돌 판정과 표시용 데이터는 같은 모양/위치를 사용한다.
- 충돌 캡슐 수를 먼저 줄이지 않고 변하지 않는 반지름·프로필 계산과 중복 갱신을 제거한다. 실제 피해 규칙을 바꾸는 충돌 시스템 교체는 성능 결과를 보고 별도 판단한다.
- 검증은 같은 개수/궤적에서 표시 OFF/ON의 그리기 호출, 몸통 갱신 시간과 렌더링 갱신 시간을 비교한다. 프레임 간격은 대기 시간을 포함할 수 있으므로 GPU 실행 시간으로 표기하지 않는다. 실제 화면 비교와 기존 피격/소거 회귀를 함께 통과해야 한다.
- `projectile_batch_renderer.gd`는 탄의 부모별로 하나를 공유한다. 같은 외형이 연속된 구간만 MultiMesh로 묶고, 그 사이의 레이저도 순서대로 그려 탄종이 섞일 때 투명도 중첩 순서를 보존한다. 개별 이동 노드와 Area2D 판정은 유지하며 풀링/충돌 시스템 전체 교체는 이번 범위가 아니다.
- 지원 범위는 현재 시험 탄의 공통 Z/기본 재질이다. 별도 Z, 개별 ShaderMaterial, Y 정렬, 다른 오브젝트와 탄마다 교차하는 그리기 순서가 필요하면 `use_batched_rendering = false`를 트리 추가 전에 설정하거나 별도 탄 컨테이너로 나눈다. 실행 중 외형 Resource 변경은 지원하지 않으며 새 설정으로 재발사한다.
- 원탄의 가장자리 평활화는 64분할 원과 투명 외곽 메시로 구현한다. 쌀탄의 24분할 외곽, 레이저 표본과 폭/색은 유지한다. 원탄 가장자리의 픽셀 단위 일치까지 보장하지 않는다. 판정 표시는 실제 원/캡슐을 인스턴스 셰이더로 그린다.
- 재현 가능한 렌더링 비교는 `tests/projectile_render_benchmark.gd`, 배치 수명·격리·혼합 순서 회귀는 `tests/projectile_batch_smoke_test.gd`다. 측정 결과를 비교할 때 실행 환경을 함께 확인한다.

#### 탄막 작성 API · 1차 구현 완료

- `.gd` 패턴은 BarrageSequence를 상속하고 인자 없는 `_init()`에서 설정만 구성한다. EnemyShootComponent.pattern_script가 있으면 기존 반복 Timer 대신 내부 BarragePlayer를 사용한다. 초기 지연·화면 진입·활성 기간은 컴포넌트, 발사 일정·배치는 패턴이 소유한다.
- 실행 복사는 기본 BarrageSequence에 데이터만 복사하며 패턴 생성자를 재실행하지 않는다. 발사 금지선은 FIRE를 건너뛰고 일정은 진행한다. 컴포넌트의 표적 조회 경로에서는 표적 부재 시 조준 Volley만 건너뛰고 다음 발사에서 재조회한다. 기존 Player의 고정 표적 모드는 트리 이탈 시 중단 계약을 유지한다.
- ACTION_RATE는 패턴 시간 배율에 적용하며 탄 이동/Behavior는 바꾸지 않는다. 초기 지연은 기존처럼 실제 게임 시간이다. 위협도 발사율은 한 주기의 FIRE 발수/WAIT 총합에 배속을 곱해 근사하고 대기가 없는 유한 패턴은 최소 0.05초로 평가한다. 반응 시간은 가장 빠른 초기 탄속으로 근사한다.

- 본 게임 Drone은 `patterns/drone_pattern.gd`, Striker·Interceptor는 `patterns/aimed_burst_pattern.gd`, Caster는 `patterns/caster_pattern.gd`를 사용한다. 모두 신규 바늘탄·직진 Behavior·공통 다이아몬드 꼬리·8초 수명을 사용한다. 기존 기본탄의 초기 확대/섬광과 시간당 파티클은 그대로 복제하지 않는다. 발사 수치·활성 조건은 각 적 기획서를 따른다. Radial 전용 컴포넌트는 제거했다. 패턴의 포화 사격 적용 범위는 [증강](augments.md)을 따른다.
- pattern_script가 없는 레거시 모드에서는 `EnemyShootComponent.barrage_shot`을 선택해 새 탄만 연결할 수도 있다. 이때 방향 주입 없는 전용 씬 발사는 기존 projectile_scene 경로를 유지하고 새 탄 생성은 deferred 단계에서 수행한다.
- Elite Awl은 이 단발 어댑터로 신규 불꽃탄을 사용한다. 이동 서브스텝·발사 난수·예고는 기존 공격 컴포넌트가 소유하며 Sequence 이식은 하지 않았다. 채택한 외형과 공격 재생 Lab은 [Elite Awl](elites/elite-awl.md#탄막-이식)을 따른다. 비교용 Legacy 구현은 제거했다.
- 위협 격자 최적화는 레거시 탄에도 적용된다. 새 MultiMesh/레이저 메쉬·판정 표시 배칭은 FoundationBullet/CurvedLaser에 적용되며 `Kind.LEGACY`는 기존 Sprite/파티클 렌더링을 사용한다.

##### 발사 일정·Behavior 표현력 확장 · 구현 완료

2026-09-17 API 검토에서 표현력 공백을 세 갈래로 나눴다. (a) `_init()`의 GDScript 루프로 단계를 펼치면 이미 가능한 것(부분 반복·다중 속도 링·버스트별 절대각)은 API 추가 없이 [작성 관용구](../barrage-api.md#작성-관용구)로 문서화한다. (b) 런타임에만 정해지는 것은 아래 원시 연산으로 추가한다. (c) 구조 결정이 필요한 것은 파라미터화를 구현하고 탄→탄 발사는 자리만 확정한다. 발사 시점 난수(jitter)는 이번 범위에서 제외했다. `await` 기반 코루틴 패턴은 사전 검증·위협 요약·저장·시간 분할 결정론을 잃으므로 채택하지 않는다.

- **패턴 파라미터** — `BarrageSequence.build(params: Dictionary)`는 기본 구현이 빈 훅이다. `EnemyShootComponent.pattern_params`(Dictionary export)를 `_init()` 다음에 `build()`로 전달하고, 검증·발사 요약·snapshot은 build 이후에 수행한다. Lab의 스크립트 로더는 빈 Dictionary를 전달하므로 패턴은 모든 키를 기본값과 함께 읽는다(`params.get("count", 3)`). `_init()`만 있는 기존 패턴은 그대로 동작한다. 적 변형(엘리트·난이도)의 수치는 패턴 상수가 아니라 적 씬의 `pattern_params`에 둔다.
- **절대 기준각** — `rotate_to(도)`는 기준각을 절대값으로 설정한다. `rotate()`와 달리 반복 간 누적하지 않는다.
- **조준 고정** — `aim()` 단계는 발사자 위치→표적 방향을 Player 상태에 잠근다. Volley의 조준 방식은 `aim` 열거값 `NONE`(아래 기준) / `EACH_SHOT`(매 FIRE 표적 재조회, 기존 `aimed = true`와 동일) / `LOCKED`(마지막 `aim()` 방향 재사용)이다. `aimed`는 호환 별칭으로 남기며 `LOCKED`를 낮추지 않는다. `aim()` 시점에 표적이 없거나 발사자와 겹치면 이전 잠금을 유지하고, 잠금이 없는 `LOCKED` Volley는 표적 없는 조준 Volley처럼 그 발사만 건너뛴다. 잠금은 새 `play`마다 초기화한다. `aim()`이 있는 Sequence는 조준 Volley와 같은 표적 요구 조건을 따른다.
- **발사자 회전 기준** — `BarrageVolley.relative_to_emitter = true`는 `aim == NONE`인 Volley의 방향을 발사자 `global_rotation`만큼 회전한다. 조준 Volley는 이미 월드 방향이므로 무시한다. `origin_offset`은 기존처럼 발사자 로컬이다.
- **Behavior easing** — `BulletAction.transition_type`/`ease_type`(Tween 열거값, 기본 LINEAR/IN_OUT)을 추가한다. 적용 대상은 turn_by·turn_to·speed_to·tint_to·opacity_to·visual/hitbox scale이며 turn_at·파동·호밍·wait는 무시한다. 빌더 `BulletBehavior.eased(trans, ease)`는 마지막 Action에, `BulletAction.eased(...)`는 병렬 자식에 사용한다. 위치 적분은 기존 1/120초 중점 근사를 그대로 쓰므로 easing이 캐시 구조를 바꾸지 않는다.
- **heading_wave 중심 규칙 변경** — 파동 중심을 최초 발사 방향에서 **Action 시작 시점의 heading**으로 바꾼다. 선회 뒤에 이어 붙인 파동이 튀지 않고 합성된다. 위상 0으로 한 주기를 마치는 기본 파동은 결과가 같다. 기준 해석기(`tests/fixtures/behavior_reference.gd`)도 같은 규칙으로 갱신했다.
- **탄→탄 발사 자리 확정(설계만)** — 분열·정지 후 재조준은 `BulletAction.Type.SPAWN`으로 둔다. payload는 `BarrageVolley` 하나이며 Action 시각에 탄의 현재 위치·heading을 기준으로 즉시 발사한다(여러 시점 분열은 SPAWN 여러 개). 실제 `advance_to`에서만 한 번 실행하고 과거/미래 조회·궤적 캐시는 SPAWN을 재실행하지 않는다. 자식 탄은 같은 월드 부모에 생성하며 재귀 깊이는 1(자식 Shot의 Behavior에 SPAWN 금지)로 시작한다. 위협도는 자식 탄을 미리 보지 못하며 이를 문서화한다. Player/Sequence 층에는 손대지 않는다. 미구현이며 구현 시 소거 XP·최대 탄 수 규칙을 먼저 정한다.
- 완료 조건: rotate_to 절대각·반복 초기화, aim()/LOCKED/EACH_SHOT 혼합 발사와 표적 이동, 잠금 없는 LOCKED 건너뛰기, 고정 표적 모드 검증, relative_to_emitter와 기본 Volley 동시 발사, aimed 호환 매핑, easing 곡선·적분 거리·병렬 자식·turn_at 무시, 선회 뒤 파동 중심, build(params) 기본값·컴포넌트 전달·위협 요약, 기존 캐시 동등성·호밍·패턴·Lab 회귀.

전체 메서드·필드·사용 예제와 단계별 이식 제안은 [탄막 API 레퍼런스](../barrage-api.md)를 참고한다. API 문서는 현재 코드의 사용 계약을 설명하며 게임 규칙은 이 문서가 정본이다.

- Easing의 보간 비율은 모든 적용 채널에서 `[0, 1]`로 제한한다. BACK·ELASTIC·SPRING의 범위 밖 오버슈트도 잘라내므로 값은 Action 시작값과 목표값 사이에 머문다. 히트박스 최대 배율은 시작값·목표값의 최댓값으로 보수적으로 계산한다.
- 반복 heading_wave는 앞 반복의 종료 heading을 다음 반복의 중심으로 사용한다. 위상이 0이 아니거나 duration이 period의 정수배가 아니면 종료 오프셋이 누적될 수 있다. 단일 파동 최적화도 일반 평가와 동일하며, 유한 반복 종료 후에는 최종 heading을 유지한다.

- `BarrageShot`(탄 설정), `BarrageVolley`(단발/부채꼴/링 배치), `BarrageSequence`(발사·대기·기준각 회전·반복), `BarragePlayer`(실행)를 분리한다. 설정은 저장 가능한 Godot Resource이며 코드에서도 메서드를 연결해 작성한다.
- 시간은 초, 속도는 px/s, 각도는 도 단위다. 기준 방향은 아래이며 양수 각도는 Godot 2D의 양수 회전이다. 부채꼴은 중심각과 전체 펼침각, 링은 끝점 중복 없는 균등 분할을 사용한다. 조준은 매 발사 때 표적의 현재 위치를 한 번 읽는다.
- `play`는 설정을 깊게 복제하고 첫 대기 전 발사를 즉시 실행한다(트리 일시정지 중이면 재개 후 실행). 물리 시간으로 진행하며 트리 일시정지와 실행기 pause/resume을 따른다. 대기 초과 시간은 다음 단계로 전달한다. 한 번의 진행은 256단계·4,096발로 제한하며 남은 단계/시간은 다음 틱으로 넘긴다. 따라잡기 발사는 현재 발사자/표적 위치를 사용하며 과거 시각의 탄 위치를 역산하지 않는다.
- `repeat(n)`은 전체 시퀀스의 총 실행 횟수(n=0은 무한)다. 회전값은 반복 간 누적하고 재생 시 초기화한다. 대기가 전혀 없는 무한 반복, 잘못된 탄 설정/발수/시간/각도는 재생 전에 거부한다.
- `stop`, 재생 교체, 발사자/탄 부모/필수 조준 대상의 삭제·트리 이탈은 이후 발사를 중단한다. 탄은 지정한 월드 부모 아래 생성하므로 발사자 삭제로 이미 발사한 탄을 지우지 않는다. 탄 부모는 발사자와 독립된 같은 뷰포트의 Node2D로 지정한다.
- 생명주기 연결은 재생마다 교체한다. 일시정지 중에도 트리 이탈 즉시 취소하며 같은 노드를 다시 추가해도 자동 재개하지 않는다. 이전 발사자의 삭제 이벤트는 교체된 재생에 영향을 주지 않는다.
- 기존 시험 장면의 발사 수·간격·좌우 선회·꽃잎 회전 수치는 유지하며 API로 옮긴다. 진행 API 확인용 회전 링 예제 Resource와 선택지를 제공한다. 본 게임 적의 탄종 배정은 별도 작업이며, 발사 후 탄별 변화는 아래 BulletBehavior를 사용한다.
- 완료 조건: 실제 탄의 위치/발수/각도, 시간 분할과 초과 시간, 설정 격리, 일시정지, 재시작/중단, 발사자 삭제와 잔존 탄, 예제 Resource 로드, 기존 피격·소거 회귀를 검증한다.

**코드 작성 예제** — 같은 뷰포트 안의 `world: Node2D`와 그 아래 독립된 `emitter: Node2D`가 있을 때:

```gdscript
var shot := BarrageShot.new()
shot.appearance = preload("res://resources/projectiles/rice.tres")
shot.behavior = BulletBehavior.new() # 빈 Behavior는 직진

var ring := BarrageVolley.new()
ring.shot = shot
ring.layout = BarrageVolley.Layout.RING
ring.count = 16
ring.speed = 95.0

var sequence := BarrageSequence.new()
sequence.fire(ring).wait(0.2).rotate(10).repeat(6)

var player := BarragePlayer.new()
world.add_child(player)
if not player.play(sequence, emitter, world):
    push_error(player.last_error)
```

- `fire(volley)`는 한 묶음을 발사한다. `wait(seconds)`는 다음 단계까지 기다린다. `rotate(degrees)`는 **이후 발사 기준각**에 더하며 이미 날아가는 탄을 돌리지 않는다. `repeat(6)`은 전체 단계를 총 6번, `repeat()`/`repeat(0)`은 무한 반복한다. 마지막 wait도 수행한 뒤 완료한다.
- `BarrageVolley.aimed = true`이면 `play(sequence, emitter, world, target)`으로 표적을 전달한다. 표적과 발사점이 일치하면 아래 방향을 사용한다. `origin_offset`은 발사자 로컬 좌표이며 발사 각도는 월드 방향 기준이다.
- 레이저는 `shot.kind = BarrageShot.Kind.TRAIL_LASER`와 `behavior`, `trail_duration`, `core_width`, `hit_width`, `lifetime`으로 구성한다. 일반 탄도 같은 `behavior`를 사용한다. `CURVED_LASER`는 이전 저장 자료를 위한 별칭이며 별도 몸체가 아니다. 레거시 기본탄은 `Kind.LEGACY`로 비교할 수 있다.
- `player.pause()`/`resume()`은 **발사 진행만** 멈추고 재개한다. 게임 전체를 멈추려면 트리 일시정지를 사용한다. `stop()`은 미래 발사만 취소한다. 자연 종료 시 `finished` 신호가 한 번 발생하며 stop/재생 교체에는 발생하지 않는다. `volley_fired(projectiles)`는 생성된 탄 목록을 반환하는 신호다. 잘못된 play는 이전 재생을 중단하고 false와 `last_error`를 반환한다.
- `steps: Array[BarrageStep]`와 `repeat_count`는 인스펙터에서도 편집할 수 있다. 실행 중 원본 변경은 다음 play에 반영한다. `.tres`의 예제는 `resources/projectiles/rotating_ring_sequence.tres`다.
- 시험: `projectiles/barrage_api_lab.tscn`에서 F6 또는 `tools/run-godot.cmd res://projectiles/barrage_api_lab.tscn`. 16발 링을 0.2초 간격으로 6회, 매회 기준각 +10°, 마지막 발사 후 1.2초 휴식하며 반복한다. 기존 시험 장면의 패턴 메뉴에서도 **API · 회전 링 연속 발사**를 선택할 수 있다.

#### 탄별 Behavior와 몸체 분리 · 구현 완료

##### 실행 상태 캐시 — 구현 완료

- 공통 Bullet Lab은 위협 계산 토글(기본 ON)과 FPS/평균 프레임 간격(ms)을 제공한다. OFF는 Lab의 ThreatMonitor 자동 샘플링을 중단하고 SPACE/위협 수치 대신 OFF를 표시한다. 다시 ON하면 측정을 초기화하고 정상 샘플 간격으로 재개한다. 선택은 패턴 변경·다시 발사·pause 후에도 유지한다. FPS는 실제 경과 시간 기준 0.5초 구간의 화면 프레임 수로 계산하며 pause 중에도 표시한다. 토글 직후에는 FPS 구간도 초기화하여 이전 모드와 섞지 않는다. 본 게임의 위협 계산 설정에는 영향을 주지 않는다.

- 일반 Behavior는 Action 경계의 누적 상태를 필요할 때만 앞으로 계산하고 보관한다. 과거/미래 조회는 경계 검색 후 현재 Action만 평가한다. 순차·병렬·반복·즉시 Action·유한 반복 종료 의미와 1/120초 중점 적분을 유지한다.
- Action 경계 비교는 1e-10초 오차를 흡수하여 경계에서 다음 단계/즉시 Action을 적용한다. 이전의 반복 뺄셈으로 소수점 경계 바로 직전 상태가 반환되던 오차를 보정한다. 병렬 자식의 완료 시각도 같은 기준을 쓴다.
- 몸체·이동·위협도는 탄별 궤적 캐시를 공유한다. 일반 경로의 동일 시각 위치 조회는 최대 2048개까지 재사용하고 상한 도달 시 조회 캐시를 비운다. 고정 적분 표본과 Action 경계 상태는 탄 수명 범위에서 필요할 때 증가하며 탄 소멸과 함께 해제된다. 직진·단일 선회·단일 방향 파동은 별도 조회 Dictionary를 거치지 않는다.
- 실제 재생 시각은 몸체 갱신의 `advance_to`에서만 전진하며 미래 조회로 바뀌지 않는다. `invalidate_prediction`은 실제 시각 이후 위치 캐시를 폐기하고 같은 입력으로 재생성한다. 정적 경로는 Action 경계 캐시를 유지한다. 호밍 경로는 아래 입력 기록과 동적 실행 상태를 사용한다. 임의의 외부 효과 적용은 아직 지원하지 않는다.
- 완료 조건: 기존 해석기와 모든 상태 채널/위치 비교, 조회 순서·프레임 분할·반복 경계 회귀, 미래 폐기 후 과거/재계산 일치, 현행 mixed_sixteen_pattern 보존 및 나이별 CPU/실제 프레임 p95 전후 비교.

##### 호밍 런타임 · 구현 완료

- `BulletBehavior.homing(max_turn_degrees_per_second, seconds)` / `BulletAction.homing(...)`을 제공한다. 선회율과 지속 시간은 명시적 양수이며 기본값은 두지 않는다. 종료 후 마지막 방향을 유지하고 이어지는 상대 선회는 실제 종료 방향을 기준으로 한다. heading 채널을 사용하므로 병렬 heading 쓰기는 거부한다.
- `BarrageShot.spawn(..., debug, target, target_resolver)`의 선택적 끝 인자로 표적과 `Callable() -> Node2D` 공급자를 전달한다. `BarragePlayer`는 play의 표적과 resolve_target을 발사된 탄에도 전달한다. `aimed`는 발사각에만 관여하며 호밍은 표적이 없어도 발사된다. 유효 표적은 같은 viewport에서 트리 안에 있고 삭제 대기 중이 아니며 위치가 유한한 Node2D다. 소실 시 실제 틱마다 공급자를 최대 한 번 호출하며 무효 결과는 무표적으로 처리한다. 발사자/공급자 소멸은 잔존 탄을 제거하지 않는다.
- 일반 탄과 TRAIL_LASER에 동일하게 적용한다. 호밍을 포함한 Behavior만 동적 실행 경로를 사용한다. 입력은 발사 시와 각 실제 갱신 구간의 시작에 한 번 관측한다. 최대 1/120초 소구간 및 Action 경계에서 적분하며, 지나온 실행 상태·위치·입력 기록을 보존한다. 조회만으로 표적 콜백을 호출하거나 실제 시간을 전진시키지 않는다. 서로 다른 입력 관측 간격은 다른 경로를 만들 수 있다.
- 예측은 마지막 관측 위치를 고정하고 다음 실제 관측 시 미래만 폐기한다. 같은 입력 기록의 과거/몸체/판정/위협도 조회는 동일한 궤적을 사용한다. pause 중 실제 관측과 이동을 멈춘다. 표적 선택 정책은 공급자에 두며 이번에는 플레이어 무기·적 배정을 바꾸지 않는다.
- Lab에 **호밍 · 원탄**과 **호밍 · 레이저**를 추가한다. 90°/s·추적 4초·수명 6초·속도 70px/s·3발 부채꼴·2초 간격의 비교 예제이며 WASD로 표적을 움직인다. `projectiles/homing_bullet_lab.tscn`에서 바로 연다.
- 완료 조건: 선회 제한·180도 동률·표적 겹침/소실/재획득/다른 viewport 거부·유한/반복/병렬 조합·탄별 격리·예측/실제 일치·과거 꼬리 보존·pause·실제 충돌·발사자 소멸 회귀. 외부 증강 효과 API는 후속 범위다.

- 대체 표적이 없으면 현재 방향으로 진행하고 다음 틱에 다시 시도한다. 표적과 탄의 위치가 같으면 방향을 유지한다. 선회는 도/초 단위 최대 선회율로 최단각을 제한하며 180도 동률은 양의 회전 방향이다. speed·시각·판정·lateral 채널과는 병렬 실행할 수 있다. lateral Action은 기존 발사 축 기준 변위를 유지한다.

##### 외부 궤도 개입 설계 · 후속 구현

- 한 틱의 적용 순서는 Behavior/호밍의 기본 heading·speed 평가 → 외부 효과 합성 → 위치 적분 → 몸체·판정 갱신이다. 외부 효과는 탄별 핸들로 등록/해제하고 활성 시간 동안 방향 오프셋 합과 비음수 속도 배율 곱을 적용한다. 서로 다른 효과는 등록 순서에 영향받지 않는다. 같은 핸들 재등록은 교체한다. 순간 반사·소유권 전환·Behavior 교체는 이 설계 범위 밖이다.
- 동적 입력은 실제 시각의 경계에 기록하고 이미 지나온 위치/레이저 꼬리를 다시 계산하지 않는다. 표적 관측이나 효과 변경 시 경계 이후 예측만 폐기한다. 호밍 예측에서는 마지막 관측 위치를 고정하며 미래의 표적 이동·재획득·새 외부 효과 발생을 가정하지 않는다. 알려진 효과 만료는 예측에 반영한다. 이 예측은 보장된 미래 경로가 아닌 현재 입력 기준 근사다.
- 외부 효과 후속 구현 시 완료 조건: 효과 중첩/만료·pause·탄별 격리, 개입 직전/직후 위치 연속성, 과거 꼬리 불변, 몸체/판정/위협도 동일 궤적 확인. 외부 효과 적용 API는 아직 노출하지 않는다.

- 공통 꼬리 입자: BarrageShot.trail_effect는 선택적 시각 효과이며 BULLET/TRAIL_LASER에 적용한다. 월드별 관리기가 입자를 소유하고 같은 텍스처·색·크기 설정을 MultiMesh로 배치한다. 탄의 이전/현재 월드 위치 사이에서 이동 거리 간격으로 방출하며 정지 중에는 방출하지 않는다. 기존 입자는 탄 소멸 후에도 수명까지 남고 트리 일시정지를 따른다.
- 관리기당 최대 4096입자, 물리 틱당 신규 256개, 탄별 갱신당 최대 64개로 제한한다. 초과 방출은 버리고 이후 몰아서 보충하지 않는다. 한 틱에 1024px 넘게 위치가 바뀌면 순간이동으로 취급해 연결 꼬리를 만들지 않는다. 입자는 장식이며 피격/소거 보상/위협도에 포함하지 않는다. 월드 제거 시 같이 정리한다.

- 일반 탄 외형에 TEXTURED를 추가한다. 중심 텍스처와 넓은/좁은 발광을 동일 텍스처의 3개 층으로 그리며 발광은 가산 블렌딩이다. 같은 텍스처·층 크기·층 색의 연속 탄들은 같은 MultiMesh를 공유한다. 서로 다른 재질 층은 별도 드로우콜이며 원탄·레이저와의 배치 순서는 유지한다.
- needle.tres는 기존 player_blaster.svg의 코어 6×8px, 넓은 발광 5.28×14.08px, 좁은 발광 3.36×8.96px와 기존 블러/색을 사용한다. TEXTURED 판정은 collision_size 직사각형이며 collision_offset으로 보정한다. 판정 배율은 크기와 오프셋 모두에 적용하고 시각 배율과 분리한다. Drone에 이 외형을 사용하며 다이아몬드 꼬리는 별도 trail_effect 설정으로 연결하며 초기 확대·섬광은 미구현이다.

- 성능 보정: 궤적 조회에서 불필요한 속성 해석을 생략하고 단일 방향 파동은 직접 평가한다. 위협도 격자는 선분의 확장 경계 안에 있는 칸만 검사하되 기존 중심점 거리 판정을 유지한다. 동일 예제의 몸체·배치·위협도 CPU 시간을 수정 전후 비교한다.

- Kind는 `BULLET`과 `TRAIL_LASER` 몸체를 구분한다. 레거시 탄은 비교용 어댑터로 유지한다. 선회/S자/파동은 Kind가 아닌 `BulletBehavior`다.
- `BulletBehavior`는 `BulletAction`의 순차·병렬 실행과 전체 반복을 제공한다. 직진은 기본 상태이며 대기 중에도 현재 방향/속도로 이동한다. 선회(by/to/at), 방향 파동, 측면 파동, 속도·색·투명도·시각 배율·판정 배율 변경을 제공한다. 보간은 기본 선형이며 지원 Action은 eased()로 Tween transition/ease를 지정할 수 있다.
- 병렬 묶음은 가장 긴 액션이 끝날 때 완료하며 같은 속성에 쓰는 액션은 거부한다. 시각 배율과 판정 배율은 독립이다. 설정을 발사 시 복제하고 위치·진행 상태·경로 캐시는 탄마다 독립적으로 관리한다.
- 이동/예측/레이저의 과거 몸통은 동일한 궤적 조회와 적분 캐시를 사용한다. 정적 Behavior는 실시간 프레임 간격과 무관하게 같은 궤적을 얻고, 호밍은 관측된 입력 기록을 기준으로 한다. 과거 기록을 새 방향으로 덮어쓰지 않는다. 실행 도중 외부에서 Behavior를 교체하는 API는 이번 범위에 포함하지 않는다.
- BulletMotion 클래스·필드·직선/파동 프리셋·변환 경로는 제거했다. 일반 탄 이동 설정은 Behavior 하나다. 레이저의 기존 선회 입력은 별도 호환 경로로 남아 있다. 본 게임 Drone은 API 발사 일정과 BULLET 몸체의 needle 텍스처 외형을 사용한다.
- Sequence는 여러 Volley를 같은 단계에서 발사하는 `fire_together`와 편의 메서드 `fire_ring`/`fire_fan`을 제공한다. 동시 묶음 전체가 진행 예산에 들어올 때 발사하며 `volley_fired`는 전체 생성 목록으로 한 번 발생한다.
- `turn_by(도, 초)`는 현재 방향에서 상대 선회, `turn_to(도, 초)`는 아래=0°인 월드 방향으로 최단 선회, `turn_at(도/초, 초)`는 일정 각속도 선회다. 완료한 방향·속도·색·배율은 다음 액션에도 유지된다.
- `heading_wave(진폭 도, 주기 초)`는 Action 시작 시점의 heading을 중심으로 한 주기 동안 방향을 왕복한다(2026-09-17 규칙 변경, 위 확장 절 참고). 계속 S자를 그리려면 `.repeat()`를 붙인다. `lateral_wave(진폭 px, 주기 초, 위상 라디안)`는 최초 발사 방향의 수직 축으로 흔들리는 변위를 추가한다.
- `tint_to`는 일반 탄의 기본색, 레이저의 기존 금색 팔레트에 곱할 색을 보간한다. 레이저의 초기 tint는 흰색이다. `opacity_to`는 전체 투명도, `visual_scale_to`는 시각 크기, `hitbox_scale_to`는 판정 크기를 독립적으로 바꾼다. 투명해져도 판정은 유지된다.
- Behavior는 최대 128단계, 병렬은 중첩 없는 최대 16개 액션이며 같은 속성에 중복으로 쓸 수 없다. 무한 반복 주기는 최소 0.1초, 배율은 0 초과 16 이하, 투명도는 0~1이다. 일반 이동 적분은 1/120초 간격 중점 근사이며 직진·기존 단일 각속도 선회는 해석식을 사용한다. 위협 반경은 전체 Behavior의 최대 판정 배율로 보수적으로 계산한다.
- 시험 진입점은 `projectiles/bullet_behavior_lab.tscn`이다. **16방향 · 원탄 + S 레이저**는 직선 원탄 8발과 +22.5° 어긋난 S 레이저 8줄을 동시에 발사한다. **Behavior · 색/크기 변화**에서는 선회·색·시각 확대를 병렬 실행하고 판정 크기는 유지한다.

**작성 예제** — 아래 설정을 `BarrageShot.behavior`에 연결한다:

```gdscript
shot.behavior = BulletBehavior.new().wait(0.3).parallel([
    BulletAction.turn_by(90, 1.2),
    BulletAction.tint_to(Color(0.15, 0.7, 1), 1.2),
    BulletAction.visual_scale_to(2.5, 1.2),
]).wait(0.3).opacity_to(0.15, 0.7)

# 저장된 16방향 예제: 두 Volley가 같은 FIRE 단계에 들어 있다.
var mixed := preload("res://resources/projectiles/mixed_sixteen_sequence.tres")
player.play(mixed, emitter, world)
```

### 일반 적 사격 안전선

- `EnemyAugmentRegistry.shot_threshold_y_ratio`의 기본값 **0.7**을 플레이필드 공통 Y 안전선으로 사용한다.
- `EnemyShootComponent.apply_shot_threshold`가 켜진 적은 중심점 Y가 `VisibleRect` 높이의 70%를 넘으면 발사하지 않는다. 즉 상단 70%에서는 발사할 수 있고 하단 30%에서는 발사하지 않는다. 값이 작을수록 더 위에서 사격을 멈춘다.
- Drone · Striker · 이를 상속한 Interceptor가 안전선을 사용한다. Elite 및 Caster/Sniper 전용 공격은 사용하지 않는다.
- 안전선은 볼리 생성 직전에 매번 공통값을 읽는다. 런타임에 공통값이 바뀌면 이미 활성화된 적용 대상도 다음 발사부터 새 값을 사용한다.

### 엘리트 이상 처치 탄소거

- Threat 엘리트 처치 시 전투를 일시정지하고 플레이필드의 `enemy_projectiles`를 즉시 제거한다. 플레이어 탄환은 제거하지 않는다.
- 제거한 적탄 1발마다 XP 1짜리 `ExperienceOrb`를 탄 위치에 생성한다.
- 엘리트의 확정 드롭을 포함해 플레이필드에 있던 모든 XP 오브를 플레이어 수집기로 강제 흡수한다. 강제 흡수는 일시정지 중에도 이동하며, 전부 실제 XP로 정산될 때까지 기다린다.
- 흡수 중에는 플레이어 오그먼트 `C` 입력과 HUD 힌트를 잠근다. 흡수가 끝난 뒤 Threat를 올리고 적 오그먼트 오퍼를 연다.
- BOSS 스텝의 게이트·보상 경로는 구현되어 같은 `BulletCancelRewardController`를 호출한다. 현재 기본 시퀀스에는 boss_preset이 없어 건너뛰며 전용 보스 콘텐츠는 미구현이다.

## 개발용 실시간 위협도 계측

`threat_monitor/threat_monitor_lab.tscn`은 에디터에서 열고 **F6**으로 바로 실행하는 전용 플레이 장면이다. 본 게임의 `gameplay.tscn`과 Encounter 시퀀스를 그대로 재생하되 함선 피격은 막아 장시간 관찰할 수 있게 한다. 이 장면의 수치는 개발 참고용이며 본 게임의 적 능력이나 스폰 규칙을 자동 변경하지 않는다.

`ThreatMonitor`는 0.2초마다 자신이 감시하는 플레이 영역 안의 적과 적탄을 읽는다. 표시 값은 다음과 같다.

| 표시 | 의미 |
|------|------|
| CURRENT | 이번 표본의 종합 위협도 0~100 |
| SMOOTH | 짧은 순간 변동을 완화한 위협도 |
| PEAK 10S | 최근 10초 안에서 가장 높았던 CURRENT |
| DOSE | 실행 시작부터 누적한 위협량(점·초) |
| ATTACK | 아래쪽 방어 구역으로 들어오는 적탄의 생성률과 현재 밀도 |
| SPACE | 방어 구역에서 1.2초 뒤 적탄·접촉 피해 몸체의 이동 경로와 Bomb 접근 영역이 막는 격자 비율 |
| REACTION | 공격 속도와 사전에 제공된 예고 시간을 1.5초 기준과 비교한 대응 부담 |
| REMOVAL | 현재 적 HP 합계를 기준 DPS 40으로 나눈 제거 시간 |
| PATTERN | 위험 칸 사이에 안전 공간이 얼마나 잘게 나뉘는지와 유효 적탄 진행 방향의 다양성 |

각 구성 값은 0~1로 제한하며 종합값은 아래처럼 계산한다.

```text
p = 0.40×ATTACK + 0.38×SPACE + 0.22×REACTION
m = p × (0.50 + 0.50×PATTERN) × (0.85 + 0.15×REMOVAL)
m = m × (1.00 + 0.55×CONCURRENCY)
CURRENT = 100 × (1 - exp(-2.2m)) / (1 - exp(-2.2))
```

ATTACK은 공격 컴포넌트가 가진 주기·묶음 수·발사 수를 초당 예상 적탄 수로 바꾸되, 플레이 영역 아래 45%에 들어오는 탄만 현재 밀도에 포함한다. 총 탄 수의 효과는 실제 SPACE 점유율에 따라 줄어든다. 따라서 위쪽으로 빠지거나 큰 틈을 남기는 탄은 수가 많아도 낮게 평가된다.

SPACE는 아래쪽 방어 구역의 12×18 표본 격자에서 적탄과 접촉 피해 몸체의 1.2초 예상 이동선, Bomb 접근 영역을 위험한 칸으로 표시한다. `정지 안전 비율`은 1-SPACE이며, 플레이어가 움직이지 않아도 피격되지 않는 후보 위치가 얼마나 남는지를 뜻한다. 몸체 판정 크기에 6px 여유를 더하므로 Awl·Interceptor·Elite Awl의 돌진뿐 아니라 일반 적과의 접촉 위험도 포함한다.

PATTERN은 안전 칸과 위험 칸의 경계가 자주 바뀌는 정도와 방어 구역으로 들어오는 탄의 진행 방향 다양성을 함께 본다. 단, SPACE를 곱해 넓은 안전 지대가 남은 성긴 패턴이 경계 수만으로 높게 평가되지 않게 한다. REACTION은 일반 사격의 플레이 영역 횡단 시간 또는 Awl·Bomb·Elite의 전체 예고 시간을 1.5초 기준과 비교한다. Sniper는 남은 조준 시간과 조준 진행률을 사용하므로 조준선이 좁혀질수록 REACTION이 올라가고, 발사된 전용 고속탄의 직선 경로도 SPACE에 포함된다. 플레이어 위치와 위험 요소 사이 거리는 사용하지 않으므로 같은 전장 상태에서 플레이어가 이동해도 위협도는 변하지 않는다.

REMOVAL은 적의 현재 HP를 기준 DPS 40으로 나눈 값이지만 직접 위협을 만들지 않는다. 실제 공격 압력이 있을 때 그 상태가 오래 지속되는 정도만 최대 15% 범위에서 보정한다. 따라서 공격이 쉬운 엘리트가 높은 체력만으로 큰 위협도를 얻지 않는다.

CONCURRENCY는 현재 공격 가능한 적이 둘 이상일 때만 적용하는 동시 대응 보정값이다. 공격원 수와 서로 다른 적 종류 수를 각각 상한이 있는 값으로 바꾸고, 종합 위협도를 최대 55%까지 높인다. 같은 Drone 20기는 한 기의 20배가 되지 않으며, 사격·저격·돌진처럼 대응 방식이 다른 혼합 편성은 같은 수의 단일 편성보다 더 크게 오른다. 공격 압력이 0이면 CONCURRENCY만으로 위협도가 생기지 않는다.

이 공식과 기준값은 첫 계측 기준이다. Encounter별 기록과 실제 피격·처치 시간의 차이가 쌓이면 기획 문서의 값과 함께 보정한다.

## 완료 조건·검증

- 플레이어 피해는 피격당 1이며 실드가 먼저 소모된다.
- 중복 치명 입력으로 점수·XP가 중복 지급되지 않는다.
- 엘리트 처치 시 적탄만 XP로 바꾸고 정산 완료 전 다음 오퍼를 열지 않는다.
- 위협도 전용 장면을 F6으로 실행하면 본 게임 Encounter가 진행되고 실시간 값과 최근 그래프가 갱신된다. Lab 레이아웃은 640×360 뷰포트 안에 들어가 위아래가 잘리지 않는다.
- 계측기는 게임 규칙을 바꾸지 않으며 감시 범위 밖의 적과 적탄은 계산에서 제외한다.
- 플레이어 위치만 바꿔서는 같은 전장 상태의 위협도가 달라지지 않는다.
- 접촉 피해를 가진 적의 현재 몸체와 예상 이동선이 SPACE에 반영된다.
- 아래쪽 방어 구역에 넓은 정지 안전 공간을 남기는 탄막은 총 탄 수가 많아도 낮게 측정된다.
- HP와 PATTERN만 있고 직접 공격 압력이 없으면 위협도는 0이다.
- Sniper 조준 중에는 발사 시점이 가까워질수록 REACTION이 오르고 전용 고속탄 경로가 SPACE에 반영된다.
- 동시에 공격 가능한 적이 많고 종류가 다양할수록 기존 공격 압력에 CONCURRENCY 보정이 적용된다.
