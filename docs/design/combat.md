# 전투

## 기획 의도

작은 피격 코어와 일관된 피격·실드 규칙으로 회피의 성공과 실패를 명확히 전달한다. 엘리트 처치 보상은 탄막 회피 구간에서 다음 선택으로 넘어가는 휴지기를 만든다.

## 확정된 현재 동작

## 물리 레이어 이름 (`project.godot`)

| Bit | 이름 |
|-----|------|
| 1 | `player_hurtbox` |
| 2 | `enemy_hurtbox` |
| 3 | `player_projectile` |
| 4 | `enemy_projectile` |

**레이어 3–4는 미사용.** 탄 Hitbox는 대개 layer 0 + hurtbox **mask**로 동작한다.

## 레이어/마스크 실사용

| 액터 | Layer | Mask |
|------|-------|------|
| Player Hurtbox | 1 | default |
| Enemy Hurtbox | 2 | 0 |
| Enemy Hitbox (몸) | 0 | 1 |
| Player Blaster Hitbox | 0 | 2 · damage **10** |
| Player Shotgun Pellet | 0 | 2 · damage **4** × 5발 |
| Curve/Counter 탄 | 0 | 1 |
| Laser RayCast | — | 2 (직접 `hurt.emit`) |

## 데미지 파이프라인

```text
Hitbox.area_entered
  → Hurtbox & not invincible
  → hit_hurtbox + hurtbox.hurt
  → HurtComponent
      → (player) incoming = 1
      → notify_hit (실드 충전 게이지 리셋)
      → 실드에 먼저 피해 적용, 남은 피해만 stats.health -= remaining
  → 생존→사망 전환이면 no_health 1회 → 파괴/점수
```

레이저는 Area 겹침을 쓰지 않고 RayCast + DamageTickTimer로 `hurt`를 직접 보낸다.

`HurtComponent.shield_component`는 플레이어에만 연결돼 있다(적은 null → 기존 동작). **플레이어가 맞는 피해는 항상 1.** 실드는 버퍼 HP라 실드 0일 때만 선체가 깎인다. 모든 피격 후 기본 0.6초 무적이며, 충격 분산 골격은 선체 피격 무적시간을 1.0초 늘려 총 1.6초로 만든다.

### 일반 적 사격 안전선

- `EnemyAugmentRegistry.shot_threshold_y_ratio`의 기본값 **0.7**을 플레이필드 공통 Y 안전선으로 사용한다.
- `EnemyShootComponent.apply_shot_threshold`가 켜진 적은 중심점 Y가 `VisibleRect` 높이의 70%를 넘으면 발사하지 않는다. 즉 상단 70%에서는 발사할 수 있고 하단 30%에서는 발사하지 않는다. 값이 작을수록 더 위에서 사격을 멈춘다.
- Drone · Striker · 이를 상속한 Interceptor가 안전선을 사용한다. Elite 및 Caster/Sniper 전용 공격은 사용하지 않는다.
- 안전선은 볼리 생성 직전에 매번 공통값을 읽는다. 런타임에 공통값이 바뀌면 이미 활성화된 적용 대상도 다음 발사부터 새 값을 사용한다.

### 엘리트 이상 처치 탄소거

- Threat 엘리트 처치 시 전투를 일시정지하고 플레이필드의 `enemy_projectiles`를 즉시 제거한다. 플레이어 탄환은 제거하지 않는다.
- 제거한 적탄 1발마다 XP 1짜리 `ExperienceOrb`를 탄 위치에 생성한다.
- 엘리트의 확정 드롭을 포함해 플레이필드에 있던 모든 XP 오브를 플레이어 수집기로 강제 흡수한다. 강제 흡수는 일시정지 중에도 이동하며, 전부 실제 XP로 정산될 때까지 기다린다.
- 흡수 중에는 플레이어 오그먼트 `C` 입력과 HUD 힌트를 잠근다. 흡수가 끝난 뒤 Threat를 올리고 적 오그먼트 오퍼를 연다.
- 보스 스폰·진행은 아직 미구현이다. 향후 보스 처치 흐름도 같은 `BulletCancelRewardController`를 호출해 동일한 탄소거·XP 회수 계약을 사용한다.

## 개발용 실시간 위협도 계측

`threat_monitor/threat_monitor_lab.tscn`은 에디터에서 열고 **F6**으로 바로 실행하는 전용 플레이 장면이다. 본 게임의 `gameplay.tscn`과 Encounter 시퀀스를 그대로 재생하되 함선 피격은 막아 장시간 관찰할 수 있게 한다. 이 장면의 수치는 개발 참고용이며 본 게임의 적 능력이나 스폰 규칙을 자동 변경하지 않는다.

`ThreatMonitor`는 0.2초마다 자신이 감시하는 플레이 영역 안의 적과 적탄을 읽는다. 표시 값은 다음과 같다.

| 표시 | 의미 |
|------|------|
| CURRENT | 이번 표본의 종합 위협도 0~100 |
| SMOOTH | 짧은 순간 변동을 완화한 위협도 |
| PEAK 10S | 최근 10초 안에서 가장 높았던 CURRENT |
| DOSE | 실행 시작부터 누적한 위협량(점·초) |
| ATTACK | 아래쪽 방어 구역으로 들어오는 적탄의 생성률과 현재 밀도 |
| SPACE | 방어 구역에서 1.2초 뒤 적탄·접촉 피해 몸체의 이동 경로와 Bomb 접근 영역이 막는 격자 비율 |
| REACTION | 공격 속도와 사전에 제공된 예고 시간을 1.5초 기준과 비교한 대응 부담 |
| REMOVAL | 현재 적 HP 합계를 기준 DPS 40으로 나눈 제거 시간 |
| PATTERN | 위험 칸 사이에 안전 공간이 얼마나 잘게 나뉘는지와 유효 적탄 진행 방향의 다양성 |

각 구성 값은 0~1로 제한하며 종합값은 아래처럼 계산한다.

```text
p = 0.40×ATTACK + 0.38×SPACE + 0.22×REACTION
m = p × (0.50 + 0.50×PATTERN) × (0.85 + 0.15×REMOVAL)
m = m × (1.00 + 0.55×CONCURRENCY)
CURRENT = 100 × (1 - exp(-2.2m)) / (1 - exp(-2.2))
```

ATTACK은 공격 컴포넌트가 가진 주기·묶음 수·발사 수를 초당 예상 적탄 수로 바꾸되, 플레이 영역 아래 45%에 들어오는 탄만 현재 밀도에 포함한다. 총 탄 수의 효과는 실제 SPACE 점유율에 따라 줄어든다. 따라서 위쪽으로 빠지거나 큰 틈을 남기는 탄은 수가 많아도 낮게 평가된다.

SPACE는 아래쪽 방어 구역의 12×18 표본 격자에서 적탄과 접촉 피해 몸체의 1.2초 예상 이동선, Bomb 접근 영역을 위험한 칸으로 표시한다. `정지 안전 비율`은 1-SPACE이며, 플레이어가 움직이지 않아도 피격되지 않는 후보 위치가 얼마나 남는지를 뜻한다. 몸체 판정 크기에 6px 여유를 더하므로 Awl·Interceptor·Elite Awl의 돌진뿐 아니라 일반 적과의 접촉 위험도 포함한다.

PATTERN은 안전 칸과 위험 칸의 경계가 자주 바뀌는 정도와 방어 구역으로 들어오는 탄의 진행 방향 다양성을 함께 본다. 단, SPACE를 곱해 넓은 안전 지대가 남은 성긴 패턴이 경계 수만으로 높게 평가되지 않게 한다. REACTION은 일반 사격의 플레이 영역 횡단 시간 또는 Awl·Bomb·Elite의 전체 예고 시간을 1.5초 기준과 비교한다. Sniper는 남은 조준 시간과 조준 진행률을 사용하므로 조준선이 좁혀질수록 REACTION이 올라가고, 발사된 전용 고속탄의 직선 경로도 SPACE에 포함된다. 플레이어 위치와 위험 요소 사이 거리는 사용하지 않으므로 같은 전장 상태에서 플레이어가 이동해도 위협도는 변하지 않는다.

REMOVAL은 적의 현재 HP를 기준 DPS 40으로 나눈 값이지만 직접 위협을 만들지 않는다. 실제 공격 압력이 있을 때 그 상태가 오래 지속되는 정도만 최대 15% 범위에서 보정한다. 따라서 공격이 쉬운 엘리트가 높은 체력만으로 큰 위협도를 얻지 않는다.

CONCURRENCY는 현재 공격 가능한 적이 둘 이상일 때만 적용하는 동시 대응 보정값이다. 공격원 수와 서로 다른 적 종류 수를 각각 상한이 있는 값으로 바꾸고, 종합 위협도를 최대 55%까지 높인다. 같은 Drone 20기는 한 기의 20배가 되지 않으며, 사격·저격·돌진처럼 대응 방식이 다른 혼합 편성은 같은 수의 단일 편성보다 더 크게 오른다. 공격 압력이 0이면 CONCURRENCY만으로 위협도가 생기지 않는다.

이 공식과 기준값은 첫 계측 기준이다. Encounter별 기록과 실제 피격·처치 시간의 차이가 쌓이면 기획 문서의 값과 함께 보정한다.

## 완료 조건·검증

- 플레이어 피해는 피격당 1이며 실드가 먼저 소모된다.
- 중복 치명 입력으로 점수·XP가 중복 지급되지 않는다.
- 엘리트 처치 시 적탄만 XP로 바꾸고 정산 완료 전 다음 오퍼를 열지 않는다.
- 위협도 전용 장면을 F6으로 실행하면 본 게임 Encounter가 진행되고 실시간 값과 최근 그래프가 갱신된다. Lab 레이아웃은 640×360 뷰포트 안에 들어가 위아래가 잘리지 않는다.
- 계측기는 게임 규칙을 바꾸지 않으며 감시 범위 밖의 적과 적탄은 계산에서 제외한다.
- 플레이어 위치만 바꿔서는 같은 전장 상태의 위협도가 달라지지 않는다.
- 접촉 피해를 가진 적의 현재 몸체와 예상 이동선이 SPACE에 반영된다.
- 아래쪽 방어 구역에 넓은 정지 안전 공간을 남기는 탄막은 총 탄 수가 많아도 낮게 측정된다.
- HP와 PATTERN만 있고 직접 공격 압력이 없으면 위협도는 0이다.
- Sniper 조준 중에는 발사 시점이 가까워질수록 REACTION이 오르고 전용 고속탄 경로가 SPACE에 반영된다.
- 동시에 공격 가능한 적이 많고 종류가 다양할수록 기존 공격 압력에 CONCURRENCY 보정이 적용된다.

검증 참고: `tests/bullet_cancel_reward_smoke_test.gd`. Godot 실행은 `tools/run-godot.cmd`를 사용한다.
